# Редакции Lite и Full и привязка устройств

Full использует пакет `com.bygram.mobile`; Lite основного модуля — `org.telegram.messenger`. Их можно установить рядом. Lite не читает чужую активность, но использует серверное подтверждение и подпись при добровольной отправке своей активности, если эти проверки включены на сервере.

## Политика проверок

Серверные параметры `account_confirmation_enabled`, `request_signature_checks_enabled` и `device_revocation_checks_enabled` независимо управляют подтверждением аккаунта, проверкой подписи запросов и учётом отзыва устройства. Если ключ отсутствует, проверка включена; в `server/activity-api/config.example.php` все три явно выключены. Проверяйте фактическую конфигурацию окружения. При выключенных подтверждении и подписи переданный Telegram ID сам по себе не доказывает владение аккаунтом. Миграция `20261024_access_policy.php` хранит результат подтверждения в `account_confirmed`.

Ниже описан путь с включёнными проверками.

## Модель лицензии

- Лицензия принадлежит Telegram ID, а не имени пользователя или номеру телефона.
- Администратор заранее добавляет Telegram ID в список активных лицензий.
- Одна лицензия разрешает не более двух одновременно привязанных устройств.
- Каждая установка Full создаёт в Android Keystore отдельную пару ключей EC P-256. Закрытый ключ не передаётся приложению, серверу или боту.
- Сервер хранит открытый ключ, идентификатор и отображаемое имя устройства, даты привязки и последней активности.
- Удаление данных приложения, переустановка без сохранения данных или сброс устройства уничтожают ключ и требуют новой привязки.

Android Keystore делает ключ неэкспортируемым и использует аппаратное хранилище, когда оно доступно. На устройствах без подходящего TEE/StrongBox остаётся программная реализация Keystore; поэтому это защита от обычного копирования APK и токенов, но не абсолютная защита от модифицированного клиента или взломанного устройства.

## Активация Full

1. Пользователь входит в нужный Telegram-аккаунт в BYgram и нажимает «Активировать Full».
2. Приложение запрашивает у сервера одноразовую попытку активации для текущего Telegram ID.
3. Приложение создаёт ключ Android Keystore и доказывает серверу владение закрытым ключом цифровой подписью одноразового challenge.
4. Приложение открывает официальный бот BYgram по одноразовой deep-link ссылке.
5. Бот сверяет `message.from.id` с Telegram ID попытки и проверяет активную лицензию.
6. При наличии свободного слота сервер привязывает устройство и выдаёт сессию, связанную с его открытым ключом.
7. Приложение получает результат опросом API и открывает функции Full.

Авторизация в Telegram внутри клиента сама по себе не считается доказательством для сервера: подтверждение выполняет бот, который получает Telegram ID непосредственно от Telegram.

Повторная активация на уже привязанном устройстве проходит без бота. Сервер сравнивает отпечаток ключа с активным устройством того же Telegram ID и проверяет подпись нового одноразового challenge. Затем он выдаёт новую сессию. Это работает после истечения refresh-токена или потери локальных токенов, пока ключ Android Keystore сохранился и устройство не отозвано. Для нового ключа, в том числе после переустановки или очистки данных, бот по-прежнему нужен.

Временный сбой сети, ответ сервера `5xx` или ограничение частоты при обновлении токена не удаляют сохранённый refresh-токен. Клиент повторит запрос позже. При явном отказе `401/403` он пытается восстановить сессию по сохранённому ключу.

## Превышение лимита

Если уже привязаны два устройства, новая попытка получает состояние `device_limit` и список этих устройств: имя, дата привязки и последняя активность. Пользователь выбирает одно устройство и подтверждает «Отвязать и активировать это устройство».

Сервер разрешает замену только попытке, уже подтверждённой тем же Telegram-аккаунтом через бота и доказавшей владение новым ключом. Операция атомарно отзывает выбранное устройство, его сессии и добавляет новое устройство. Нельзя удалить устройство другого Telegram ID или передать произвольный идентификатор.

## Проверка защищённых запросов

Сессия Full связана с `device_id` и открытым ключом. Защищённый запрос содержит bearer-токен, метку времени, одноразовый nonce и подпись канонической строки с HTTP-методом, путём и хешем тела. Сервер проверяет:

- активность лицензии и устройства;
- соответствие сессии устройству;
- допустимое отклонение времени;
- уникальность nonce;
- подпись запроса сохранённым открытым ключом.

Отзыв устройства немедленно аннулирует все его refresh/access-сессии.

## Серверные состояния активации

- `pending_proof` — сервер ждёт доказательство владения ключом;
- `pending_telegram` — ключ подтверждён, сервер ждёт запуск бота;
- `active` — устройство привязано, сессия выдана;
- `device_limit` — Telegram подтверждён, требуется выбрать устройство для замены;
- `expired` — одноразовая попытка истекла;
- `denied` — лицензия отсутствует, отключена или истекла.

Попытки активации и nonce имеют срок жизни, хранятся только в виде стойких случайных значений/хешей и не могут использоваться повторно после завершения.

## Сборка и границы редакций

Редакция задаётся на этапе Gradle-сборки и отражается в имени APK. В обеих редакциях сохраняются `com.bygram.mobile`, версия клиента и подпись. Список функций, исключённых из Lite, должен находиться в одном месте; на первом этапе к Full относится существующая платная функция «Кто с кем общается?». Новые платные функции добавляются в этот список вместе с проверкой, что Lite не содержит доступной точки входа и не вызывает соответствующий API.

Команды и точные пути артефактов приведены в [инструкции по сборке](build.md). Контракт проверяется командой:

```powershell
python Tools/check_bygram_editions.py
```

## Развёртывание сервера

Для существующей базы один раз выполните `server/activity-api/migrations/20260915_device_licensing.php` в контексте, где переменная `$pdo` содержит настроенное PDO-подключение. Миграция создаёт `licensed_devices`, `device_activations`, добавляет `activity_sessions.device_id` и отзывает прежние непривязанные сессии.

В закрытом `config.php` нужны `bot_token` и секрет webhook. Username бота хранится в `app_settings.bot_username` и используется для привязки устройства; ссылка на покупку лицензии берётся из `app_settings.manager_username`. Обработчик `bot.php` принимает только запросы с корректным заголовком Telegram `X-Telegram-Bot-Api-Secret-Token`; в текущей конфигурации также поддерживается прежнее имя параметра `webhook_secret`.

Админ-панель в браузере использует только Telegram Login Widget. После проверки HMAC-подписи сервер создаёт защищённую PHP-сессию (`Secure`, `HttpOnly`, `SameSite=Lax`); API панели и загрузка APK принимают только эту сессию. Домен `byxarek.site` и callback `/TEST-PROJECT/BYgram/api/admin-login.php` должны быть разрешены для бота в разделе Login Widget у @BotFather.

Текущая панель содержит обзор, BYgram-значки, Full-лицензии и привязанные устройства, релиз APK, настройки бота и список администраторов для владельца. Разделы старой платёжной системы (цены, промокоды, рефералы, реквизиты и заказы) и их действия удалены из API панели; публичные маршруты приложения и исторические данные этим изменением не затрагиваются.

После загрузки файлов зарегистрируйте HTTPS URL `.../api/bot.php` через Telegram `setWebhook`, передав тот же `secret_token`. Не записывайте token или secret в командные примеры, логи и release metadata.

## Восстановление и поддержка

- Проверка повторной активации: на уже подтверждённом устройстве очистите только локальные `access`/`refresh` токены, сохранив Android Keystore, затем откройте платный раздел. Сервер должен вернуть `active` без ссылки на бота. На новом ключе ответ должен остаться `pending_telegram`.
- При недоступном сервере обновление токена должно показать временную ошибку и сохранить refresh-токен для следующей попытки.
- Пользователь может отвязать устройство при активации третьего устройства.
- Администратор может отозвать конкретное устройство или всю лицензию.
- Потерянное устройство считается активным до явного отзыва.
- Смена Telegram username не влияет на лицензию; смена Telegram ID требует новой лицензии.
- Серверные секреты и токен бота находятся только в конфигурации сервера и никогда не включаются в APK, репозиторий или документацию.
