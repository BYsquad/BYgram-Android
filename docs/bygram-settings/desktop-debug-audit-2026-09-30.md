# Проверка Windows Debug от 30.09.2026

Проверены исходники блоков BYgram, локальные проверки и часть UI на двух уже подключённых аккаунтах. Это не подтверждение проверки всех сценариев Telegram или всех функций Android, перенесённых в Windows. QA-сообщения отправлялись только в разрешённую переписку с BYgram Manager. Открытие регистрации просмотров и пункта авторизации Full автоматически запускало служебный /start у бота BYgram; ответ подтверждения получен.

## Исправления

1. Синхронные диалоги BYgram открывались с анимацией перед вложенным `QEventLoop`: редактор статусов перехватывал ввод, но окно оставалось невидимым. В общем `core/bygram_dialogs.cpp` Confirm/Input/Choose показываются без анимации; GenericBox получает внутренний фокус. Проверены выбор десяти действий, открытие поля, ввод, отмена и отказ сохранить 65 символов. Значение на сервер не менялось.
2. Даты прочтения после перерыва в сохранении заполняли пропущенные сообщения новой датой. В `core/bygram_read_dates.h` начало диапазона учитывает фактический previous read marker. Регрессия в `tools/bygram/text_test.cpp`: ранее сохранено до 11, фактически прочитано до 20, новое обновление до 25; сообщение 15 остаётся без даты, сообщение 21 получает новую дату. Проверка сначала падала, после исправления проходит.
3. Меню Spy было подключено только к `HistoryView::ListWidget`, а обычный чат использует `HistoryInner`. Общий `AddBygramMessageActions` теперь используется обоими меню. В обычной переписке появились `Edit history` и `Read on`; исходный текст и дата сохранились после перезапуска.
4. Native QMessageBox истории правок имел заголовок `Edit history` и не попадал в обработчик закрытия приватных окон при passcode lock. Добавлено существующее свойство `bygram_private_dialog`. Обработчик `Api` закрывает такое окно при блокировке. Сборка проверена; сам сценарий блокировки с установленным кодом требует ручной проверки владельцем аккаунта.

## Проверенные сценарии

| Блок | Результат |
|---|---|
| Настройки | Раздел открывается; параметры сохраняются после перезапуска. Ghost скрывает дополнительные параметры при выключенном master. |
| Ghost: прочтение | Manager отправил QA-сообщение. Получатель открыл его с Ghost, непрочитанная отметка и отсутствие даты прочтения у отправителя сохранились. После выключения Ghost и повторного открытия непрочитанная отметка снялась. |
| Spy: правки и даты | QA-текст изменён с версии 1 на версию 2. История содержит версию 1; дата прочтения видна в меню. Оба значения пережили перезапуск. |
| Spy: удаления | В разрешённой переписке включено автоудаление 7 дней. Эти сообщения имеют TTL и намеренно не архивируются. Три QA-сообщения удалены у обоих участников; положительный тест архива без TTL пока не выполнен. |
| Скрытые чаты | Пустой список показывает «Скрытых чатов нет.». Установка PIN и проверки обходов не выполнялись. |
| Скругление аватаров | Ползунок меняет предпросмотр и аватары в списке; проверены квадрат и круг. Исходное значение 0 восстановлено. |
| Музыка | Крупная карточка показывает название/исполнителя и placeholder при отсутствии загруженной обложки. Нажатие открывает штатный плейлист. Воспроизведение и разные форматы обложек не проверялись. |
| Кастомные статусы | Выбор всех десяти действий виден; поле принимает ввод; 65 символов отклоняются; отмена работает. Подписанная публикация и отображение всех действий на втором клиенте не проверялись. |
| Просмотры профиля | Подтверждение через бота, загрузка production-списка, локальное время, отметка нового посетителя и переход строки в правильный Telegram-профиль. Полная матрица взаимного согласия/отключения/фоновых уведомлений не проверялась. |
| Zalgo, PIN/пароли, JSON/ACL, DPAPI, CNG | `bygram_text_check` и `bygram_windows_check` проходят. Это локальные проверки, не замена UI-проверкам приватности и серверного лицензирования. |

Не проверены: положительное сохранение удалённых сообщений без TTL, медиа/альбомы/темы/выгруженная история, ошибки диска, очистка пользовательского архива, обходы защиты чатов, Ghost stories/реакции/read-on-actions/набора на двух одновременно видимых клиентах, online-history, лицензия Full/отзыв/ACL, назначение значков, noforwards и все варианты DPI/RTL. Экспорт и сброс требуют отдельной проверки UI. Недостающие функции и ограничения переноса перечислены в [desktop-port-status.md](desktop-port-status.md).

Ghost, три переключателя Spy и музыка возвращены в исходное выключенное состояние; остальные настройки не изменены. Автоудаление 7 дней сохранено. Кэш и история Spy других переписок не очищались. Во время разрешённого включения Spy клиент мог сохранять обычные обновления других диалогов в локальный кэш.

## Проверки и артефакты

Windows x64 Debug: `C:/project/BYgram-desktop/output/BYgram-debug-fixed.exe`. Android Full Debug: `C:/project/BYgram-mobile/output/BYgram-full-debug.apk`, основной package `com.bygram.mobile`. Версии клиентов, зависимости и Android-код в ходе этого аудита не менялись. Новые UI-фразы не добавлялись. На итоговом EXE повторно прошли UI-проверки выбора действия и открытия поля; оба имени EXE содержат одинаковую исправленную сборку.

Из desktop checkout в x64 Native Tools environment:

```powershell
cmake --build out/bygram-check --config Debug -- /m:2 /clp:ErrorsOnly
./out/bygram-check/Debug/bygram_text_check.exe
./out/bygram-check/Debug/bygram_windows_check.exe
cmake --build out --config Debug --target Telegram --parallel 4
git diff --check
```

Минимальные UI-проверки находятся в `tools/bygram/ui_check.mjs`. В Computer Use node_repl после открытия редактора и свежего `sky.get_window_state({window, include_text: true})`:

```javascript
globalThis.qa = await import('file:///C:/project/BYgram-desktop/tdesktop/tools/bygram/ui_check.mjs');
qa.checkTypingChooser(state); // после выбора «Изменить статусы набора»
qa.checkTypingInput(state); // после нажатия на действие
```

Отдельно владелец открывает историю правок и вручную блокирует клиент с уже настроенным кодом; затем выполняется `qa.checkEditHistoryClosed(await sky.list_windows())`. Не создавайте код блокировки ради автоматизации проверки. UIA может показывать прежнее focused_element у вложенного диалога; положение каретки и введённый текст дополнительно проверяются по свежему снимку окна.
