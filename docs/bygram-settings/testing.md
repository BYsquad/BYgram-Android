# Проверка изменений настроек BYgram

## Перед любой сборкой

```powershell
python Tools/check_bygram_settings_fixes.py
```

Не меняйте `APP_VERSION_*` без отдельного запроса. `APP_PACKAGE` должен оставаться `com.bygram.mobile`.

## Быстрые статические проверки

```powershell
$checkDir = Join-Path $env:TEMP 'bygram-text-check'
New-Item -ItemType Directory -Force -Path $checkDir | Out-Null
javac -d $checkDir TMessagesProj/src/main/java/org/telegram/messenger/BygramTextUtils.java Tools/BygramTextCheck.java
java -cp $checkDir BygramTextCheck
python Tools/check_bygram_md3_geometry.py
python Tools/check_bygram_settings_fixes.py
php -l server/activity-api/index.php
php -l server/activity-api/admin-api.php
$env:BYGRAM_TEST_LOCAL='1'
php -d zend.assertions=1 -d assert.exception=1 server/activity-api/self-test.php
```

Сборочные команды и пути APK: [инструкция по сборке](../build.md).

## Smoke test на авторизованном устройстве

1. Убедиться, что тестируется APK из текущего дерева: package/versionCode/versionName.
2. Открыть каждый дочерний экран раздела.
3. Для каждого switch: изменить, уйти/вернуться, force-stop/relaunch, проверить persistence и consumer.
4. Проверить 3 launcher icons, вернуть исходную.
5. Проверить avatar slider на 0, промежуточном значении и 28, включая forum avatar.
6. Раскрыть MD3; проверить счётчик и компоненты. Проверить штатный Liquid Glass в «Настройки чата → Анимации → Анимации в чатах».
7. Экспортировать JSON, проверить allowlist и отсутствие history/viewers/tokens.
8. Reset/clear подтверждать только на чистом тестовом аккаунте; проверить restart.
9. Восстановить исходные пользовательские значения.

Для UI observation используйте `android layout`; screenshot — только если layout не отражает экран. `Tools/check_bygram_preferences.py` использует текущую карту «Кастомизация / Другое / Ghost / Spy» и `android layout`, а не legacy `uiautomator dump`. UI-сценарии требуют разблокированного авторизованного устройства.

## Activity integration

Нужны минимум два лицензированных test accounts и один невыбранный/нелицензированный. Проверяются challenge identity, viewers ACL, publish/get, TTL, background clear, token refresh, revoke и смена account. Подробный сценарий: [activity-sharing.md](activity-sharing.md#интеграционный-тест).

## Статусы печати и значки

1. На тестовых Lite и Full без изменения версии открыть личный чат на аккаунтах A и B; в Lite убедиться, что кнопки статусов нет и кастомные статусы не отображаются.
2. На A в Full задать фразы для текста, записи голоса, видео и видеосообщения. На уже привязанном устройстве публикация должна пройти без отдельного подтверждения через бота.
3. Начать каждое действие на A; на B проверить кастомную фразу. В обычном Telegram должен остаться стандартный статус. После удаления фразы и публикации в BYgram снова показывается стандартный статус (с учётом кеша до 7 секунд).
4. Отозвать устройство Full или лицензию и проверить, что его ключ больше не даёт право публикации без независимой привязки статусов.

## Скрытые и запароленные чаты

На Lite и Full проверить личный чат, группу и канал: в настройках сверху видны только выбранные диалоги, у каждого есть аватар и текст последнего сообщения, «+» справа в заголовке открывает обычный список чатов, добавление возвращает диалог в верхний список; проверить также удаление. Затем проверить обычный список, архив и поиск по имени/сообщениям. После ввода правильного числового кода в поиске должна появиться и выбраться вкладка «Скрытые чаты»; неверный код ничего не открывает. Закрыть поиск и снова ввести обычный запрос: вкладка и скрытые диалоги должны исчезнуть, обычные результаты — появиться. Проверить смену кода с правильным и неправильным старым кодом. Для каждого запароленного диалога проверить открытие из списка, ссылки, уведомления и после restart, неверный пароль, смену и снятие пароля, красный предпросмотр «Скрыто 🔒». Уведомление скрытого чата должно показывать «Откройте, чтобы прочитать», а нажатие — список чатов. Проверить оба вида защиты одновременно и отдельно для двух Telegram account.

Для медиа проверить «Сохранить в галерею» в просмотрщике и меню чата для обычных фото, видео и кружков при `noforwards`, а также для уже купленного за звёзды видео. Переслать защищённый текст, фото, видео, кружок и купленный контент в личный чат и группу: получатель должен увидеть новую копию без исходной отметки автора. Проверить, что до покупки доступно только превью. Отдельно проверить пересылку из просмотра медиа, профиля и аудиоплеера.

Для Spy: удалить входящее сообщение отправителем, убедиться, что оно сохранено со значком, затем повторно удалить его локально и убедиться, что оно исчезло после перезапуска.
5. Выдать в админ панели значки тестовому пользователю и тестовой группе/каналу по ID. Проверить изображения после имени в списке чатов, заголовке чата, профиле и имени автора сообщения в группе; нажатие должно показать соответствующий текст внизу экрана. Если значок назначен самому пользователю, проверить его отсутствие в заголовке «Избранного». Удалить назначения и проверить исчезновение после обновления кеша.
6. Для активности Full проверить обновление у наблюдателя каждые 7 секунд; Lite не публикует платную активность.

## Критерии готовности

- Нет crash/ANR при быстрых toggles и navigation.
- UI state после restart совпадает с consumer state.
- Global/account scope проверен сменой Telegram account.
- Privacy data не уходит до opt-in.
- Reset/clear удаляет ровно перечисленный scope.
- Все новые строки есть в английском каталоге [BYgram-translations](https://github.com/BYxarek/BYgram-translations) и в приложении; проверенные переводы импортированы из публичного каталога.
- Licensed activity test пройден на контролируемом test dataset.
