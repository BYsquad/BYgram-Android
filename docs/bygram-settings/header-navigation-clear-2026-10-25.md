# Остатки аватара и заголовков при навигации — 25.10.2026

Исправлен Android-интерфейс всех страниц настроек BYgram, включая главную,
вложенные категории и просмотр посетителя профиля. Изменяется штатная область
ActionBar Telegram, а не только пользовательские настройки оформления.

Первоначальная причина: содержимое фрагмента начинается ниже ActionBar. После удаления
подложки прозрачная панель не закрашивала оставшиеся пиксели предыдущего
экрана: верх аватара профиля, кнопки и заголовки вложенных страниц.

Общая база `BygramSettingsPage` включает непрозрачную заливку цветом
`windowBackgroundGray` перед отрисовкой панели. Цвет читается из текущей темы
при каждом рисовании. Стеклянные кнопки остаются, затемнение/градиент не
возвращаются. Фон не зависит от `View.background`, который сбрасывается при
инициализации стекла на первом измерении. Другие страницы сохраняют поведение.

Проверки: `python Tools/check_bygram_settings_header_clear.py` исполняет
реальный Java-метод `ActionBar.draw`: повторное перекрытие остатков аватара и
текста, смена темы, SDK 23/31/36, fallback без стекла и защита от рекурсии.
`check_bygram_page_headers.py` и 55 контрактов `check_bygram_settings_fixes.py`
проходят. Это проверка логики рисования, не визуальный тест на Android.

Один итоговый APK: `output/BYgram-settings-header-clear-2026-10-25.apk`.
Сборка Full Debug успешна, подпись v1/v2 и бинарная локализация проверены.
ADB не обнаружил устройств; визуальная проверка переходов остаётся необходимой.
APK включает существующие изменения Android-кода рабочего дерева.

## Повторное исправление после проверки на телефоне

Пользователь подтвердил, что первый APK не устранил остатки аватара и кнопок.
Проверка DEX показала: исправленный метод и его вызов присутствовали в APK.
Однако Android пропускает `View.draw()` у ViewGroup без фона при активном
`WILL_NOT_DRAW` и вызывает `dispatchDraw()` напрямую, в том числе при записи
аппаратного RenderNode. Это подтверждено установленными исходниками SDK 36,
`android/view/View.java`, методы `updateDisplayListIfDirty` и `draw`.
Инициализация стекла убирает фон панели, делая этот путь актуальным.

`setOpaquePageBackground` теперь вызывает `setWillNotDraw(false)`, чтобы
заливка и подготовка стекла в `ActionBar.draw()` выполнялись при отрисовке
из родителя. Первоначальный JVM-тест вызывал `draw()` напрямую и не проверял
этот путь; исправленный тест проходит через выбор между `draw()` и
`dispatchDraw()` и моделирует удаление фона после включения заливки.
Первый APK `BYgram-settings-header-clear-2026-10-25.apk` считать неудачным
исправлением; для установки будет подготовлен новый файл с пометкой `v2`.

Дефект первого APK воспроизведён на `medium_phone` (Android 16/API 36):
вход из штатных настроек оставляет часть аватара и правое меню; переходы
«Кастомизация → назад → Шпион → назад» оставляют следы стрелок и заголовков.
Скриншоты: `output/header-v1-root-emulator.png`,
`output/header-v1-navigation-emulator.png`. Обновлённый JVM-тест отклоняет
старый код с `AssertionError: Previous page leaked` и проходит с исправлением.

Итоговый `output/BYgram-settings-header-clear-v2-2026-10-25.apk` установлен
поверх предыдущего через `adb install -r`. На том же маршруте остаток аватара
и меню исчезли; после возврата из «Кастомизации» и «Шпиона» нет следов кнопок
и заголовков. Скриншоты `output/header-v2-root-emulator.png`,
`output/header-v2-spy-emulator.png`, `output/header-v2-navigation-emulator.png`.
Crash buffer пуст; подпись и бинарные переводы проверены. Настоящий телефон
не подключён.

Маршрут повторён также в тёмной теме после перезапуска приложения: главная,
«Кастомизация», возврат, «Шпион», возврат — без остатков аватара, меню и
заголовков. Скриншоты `output/header-v2-dark-root-emulator.png`,
`output/header-v2-dark-spy-emulator.png`,
`output/header-v2-dark-navigation-emulator.png`. Системный night mode эмулятора
возвращён в исходное значение `no`.
