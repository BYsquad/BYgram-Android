## Исправленные пересечения

1. **Сохранение удалённых сообщений Spy и состояние шифрования комментария кошелька.**
   Оба проекта использовали `FLAG_14` в `MessageCustomParamsHelper.Params_v1`.
   За Spy оставлен бит 14, чтобы старые локальные данные читались без миграции.
   Новое состояние кошелька читает и пишет бит 15. Иначе перевод средств мог
   получить отметку удалённого сообщения, а сохранённое сообщение — чужой флаг.
   Исполняемый тест проверяет четыре комбинации флагов, повторное чтение,
   копирование Spy и подавление preparing после появления ciphertext.
2. **Номера действий меню чата.** Новый `OPTION_SEND_MONEY=117` пересекался с
   историей редактирования BYgram. Действия BYgram перенесены на `1001..1005`;
   все обработчики и построители меню используют именованные константы.
   Добавлена проверка уникальности всех числовых `OPTION_*`.
3. **QR-коды.** Сохранён логотип BYgram для обычного QR и новый переданный
   `centerDrawable` для кошелька. Пользовательский drawable имеет приоритет.
4. **Настройки, камера и биометрия.** Вход BYgram с ID 1000 сохранён рядом с
   новыми настройками кошелька. Поля zoom BYgram и новые поля синхронизации
   переключения камеры объединены. Удалён старый неиспользуемый внутренний
   `FingerprintDialog`, как в upstream; новая реализация блокировки сохранена.
5. **Строки и редактирование сообщений.** Добавлены новые строки Telegram,
   включая предупреждение об удалении резервных копий кошелька при выходе,
   с сохранением названия BYgram. Исправление даты редактирования Telegram
   объединено с существующим выражением BYgram.

## Проверки и ограничения

Проходят:

- `Tools/check_bygram_settings_fixes.py` — 44 контракта;
- `Tools/check_bygram_editions.py` — Lite/Full, активация устройств;
- `Tools/check_bygram_md3_geometry.py` — оформление, версия/package;
- `Tools/check_bygram_profile_activity.py` — активность и геометрия профиля;
- `Tools/BygramTextCheck.java` — Unicode, фильтр Zalgo, ID, пути и калькулятор;
- `Tools/BygramMessageParamsCheck.java` — реальная сериализация локальных параметров без JNI.

Две прежние статические проверки уже падали до обновления. Они ожидали
интервал активности 20 секунд, прямую корректировку высоты и удалённые
кастомные placements Liquid Glass. Ожидания приведены к существующей
реализации: 7 секунд, общий helper геометрии и штатный Liquid Glass Telegram.

Gradle завершился с `BUILD SUCCESSFUL` для обеих редакций:

```powershell
java -classpath .\gradle\wrapper\gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain -PBYGRAM_EDITION=lite :TMessagesProj_App:compileAfatDebugJavaWithJavac
java -classpath .\gradle\wrapper\gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain -PBYGRAM_EDITION=full '-Pandroid.injected.build.abi=arm64-v8a' :TMessagesProj_App:compileAfatDebugJavaWithJavac :TMessagesProj:externalNativeBuildDebug
```

Lite: 209 задач, 6 мин 37 с. Full и native ARM64: 236 задач, 7 мин 11 с.
Нативная `libtmessages.49.so` с обновлёнными tgnet, WebRTC/tgcalls,
кошельком и Prisma успешно скомпилирована и слинкована.
Логи: `output/telegram-upgrade-compile-lite.log` и
`output/telegram-upgrade-compile-full-native.log` (локальные, не отслеживаются Git).
Проверки Python выполнены bundled Python Codex: `python` в PATH этой машины
указывает на Windows Store alias.

Сборки сохраняют предупреждения о Java 8 под JDK 21, частично мигрированных
AndroidX-зависимостях, локализованных ресурсах без default value, deprecated
Gradle API и предупреждения C++ из upstream/WebRTC. Ошибок компиляции или
линковки нет. Release/R8, упаковка APK и native-сборки других ABI не запускались.
Оставленных известных конфликтов интеграции BYgram по результатам этой
проверки нет; готовность к публикации зависит от проверок ниже.

Android-устройств через ADB нет. Не выполнены UI smoke tests, перезапуск с
изменением переключателей, обновление поверх установленного APK, сценарии
на двух аккаунтах, лицензирование и backend integration. Перед релизом
обязательны сценарии из [testing.md](testing.md), особенно защита чатов,
Ghost/Spy и работа камеры/звонков после обновления native-кода.
Наличие сохранённых вызовов и успешная компиляция не доказывают работу
этих сценариев на устройстве. APK на сервер не публиковался.
