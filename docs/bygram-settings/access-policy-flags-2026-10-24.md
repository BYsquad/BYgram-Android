# Флаги проверки доступа — 24.10.2026

На production в `api/config.php` установлены:

```php
'license_checks_enabled' => false,
'account_confirmation_enabled' => false,
'request_signature_checks_enabled' => false,
'device_revocation_checks_enabled' => false,
```

Каждая проверка независимо возвращается значением `true`. Код сохранён.
У трёх новых флагов отсутствие ключа означает `true`; в production и примере
конфигурации значения явно установлены в `false` по запросу владельца.

- Подтверждение: новый Full-ключ получает сессию без бота; независимая регистрация
  ключа статусов/фона возвращает `registered=true`. Android и iOS автоматически
  повторяют исходное действие после такой регистрации.
- Подписи: выключена проверка клиентских HTTP-подписей, доказательств устройства,
  timestamp/nonce. При выключении nonce не записывается, поэтому пустые nonce
  не сталкиваются с 409. При включении прежняя защита от повторов возвращается.
  Формат и пригодность сохраняемого публичного ключа проверяются всегда.
- Отзыв: отметки устройств и связанных с ними сессий временно не блокируют
  запросы, refresh и восстановление. Записи сохраняются. Включение возвращает
  блокировку; отозванный ключ не активируется автоматически без подтверждения.

Bearer-токены Full API, сроки access/refresh, валидация данных, rate limits,
категории доступа зрителей и проверки администратора сохранены. Подписи вебхука
бота, платежей, входа администратора и ссылок аватаров флагами не отключаются.

**Риск:** при регистрации сервер доверяет заявленному Telegram ID, поэтому
возможна подмена аккаунта. При выключенных подписях и подтверждении API фона,
статусов и посетителей принимает переданный ID без криптографической проверки
владельца. Выдача токена Full API также не подтверждает принадлежность этого ID.

Миграция `migrations/20261024_access_policy.php` добавляет `account_confirmed`
в `licensed_devices` и `typing_devices`. Прежние подтверждённые записи получают
`1`, новые ключи без бота — `0`. Включение подтверждения блокирует их запросы и
уже выданные токены до настоящего подтверждения; бот переводит запись в `1`.
Миграция повторяема, записи устройств, лицензии и сессии не удаляются.

Проверено: реальные HTTP-запросы ко временной MySQL БД, все восемь комбинаций
трёх флагов; подписи/replay; активация без бота; возврат подтверждения; отказ
отозванным устройствам, access и refresh после возврата отзыва; сроки токенов;
валидация данных; повторная миграция старой схемы. Тот же прогон выполнен с
точными объединёнными production-файлами. PHP self-test с assert — по 12 сценариев
при всех включённых и выключенных проверках. 55 контрактов настроек и Lite/Full — PASS.
