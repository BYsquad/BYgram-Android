# Фон профиля, события удаления и кастомизация — 23.10.2026

## Поведение

- При сохранении удалённого чата режимом «Шпион» время наблюдения удаления записывается в локальные параметры последнего сохранённого сообщения. Плашка «Чат удалён …» остаётся у этого сообщения после перезапуска и поступления новых сообщений. Обычное удаление отдельных сообщений не создаёт событие удаления всего чата. Уже удалённые до обновления чаты не получают выдуманное время удаления. Удаление сохранённой истории удаляет и её плашки.
- Android использует `bygramChatDeletedAt` и отдельный бит 16 локальных параметров v1; прежние биты Spy (14) и кошелька (15) сохранены. Плашка рисуется под сообщением, участвует в измерении строки и чтении TalkBack. iOS хранит дополнительное поле `chatDeletedAt` в `BygramDeletedMessageAttribute` и создаёт локальную служебную строку при построении истории. Её индекс привязан к сообщению, включая сообщения с одинаковой секундой отправки. События не отправляются на сервер BYgram.
- В кастомизации можно выбрать публичный фон профиля: JPEG, PNG, WebP или GIF, до 4 МиБ, до 4096 × 4096. Файл публикуется для текущего Telegram ID и показывается при открытии профиля в BYgram на обеих платформах. Поверх фона остаётся оттенок темы для читаемости. Удалить фон можно в том же разделе. Локальный переключатель `bygram_hide_profile_backgrounds` отключает загрузку чужих фонов; свой фон остаётся виден. Файл не включается в экспорт настроек.
- Для первой публикации нужен ключ, подтверждённый ботом, либо уже активированное Full-устройство. С 24.10.2026 после подтверждения и возвращения в приложение публикация повторяется автоматически; кнопка удалена. iOS ограничивает декодирование GIF 60 уменьшенными кадрами для ограничения памяти; длительность цикла оценивается по выбранным кадрам, частота кадров длинных GIF уменьшается.
- `bygram_keep_search_collapsed` действует только вместе с `bygram_collapse_search_on_start`. Подпункт виден только при включённом родительском переключателе. Протягивание списка не раскрывает поле; явный вход в поиск остаётся доступен. Android убирает и высоту скрытого поля, сохраняя независимое раскрытие историй. На iOS используется компактное состояние штатного поиска.
- Предпросмотр заголовка использует имя/username текущего аккаунта, выбранное выравнивание и его настоящий эмодзи-статус. Android объединяет прежние страницы профиля и общих настроек в одну страницу с разделами. Публичные адреса `general.*` и `profile.*` сохранены и направляются к нужной строке.
- Обычный Android-чат теперь регистрирует `ChatAvatarContainer` в ActionBar, как комментарии к каналам. На iOS общий фон одиночной кнопки аватара получает радиус от узла аватара, включая промежуточные состояния анимации и отдельную кнопку боковой колонки.

## Сервер

`profile_background_put`: подписанный POST с `user_id` и `image` (base64, пустая строка удаляет фон). Сервер проверяет подтверждённый ключ, подпись всего тела, timestamp и одноразовый nonce; заголовок запроса использует прежний контракт P-256. Тип и размеры определяются по содержимому, SVG не принимается. Лимит тела увеличен до 6 000 000 байт только для этой операции; у остальных действий остаётся 16 КиБ.

`profile_background_get`: POST с `owner_id`, возвращает `revision` (SHA-256) и `mime`, либо пустые строки. `profile-background.php?user_id=…&v=…` отдаёт исходные байты с правильным Content-Type, nosniff и ETag. Старая revision после замены/удаления не получает новое содержимое. Максимальный кеш файла — 5 минут.

Миграция: `server/activity-api/migrations/20261023_profile_backgrounds.php`; таблица `profile_backgrounds` добавлена также в schema.sql. В production применена идемпотентная миграция; обновлены index.php, обработчик файла, валидатор и .htaccess. Файлы проверены чтением по FTP. Временный обработчик миграции удалён. Резервные копии затрагиваемых существующих файлов — `output/prod-background-backup-2026-10-23/`. Существующий production schema.sql сохранён: он отличается от HEAD и не используется новым обработчиком в runtime.

## Проверки

- `php -d zend.assertions=1 -d assert.exception=1 server/activity-api/self-test.php` при `BYGRAM_TEST_LOCAL=1`, `BYGRAM_TEST_DB_HOST=127.0.0.1`: миграция дважды, PNG/GIF, отклонение неподдерживаемого типа/размера/геометрии, двоичное хранение и удаление — PASS. Остальные проверки self-test также PASS. В этом Windows-окружении DNS-имя `MySQL` недоступно, локальный тестовый MySQL доступен на 127.0.0.1:3306 с указанной тестовой учётной записью.
- `python Tools/check_bygram_background_api.py`: настоящий HTTP API на временном PHP-сервере и отдельной временной тестовой БД; подпись, чужой владелец, повтор nonce, загрузка/скачивание GIF, неверное изображение и удаление — PASS. Процесс сервера останавливается, тестовая БД удаляется.
- Production smoke: пустой профиль — 200, неподписанная запись — 401, неправильный owner_id — 400. Тестовые фоны в production не публиковались.
- `BygramMessageParamsCheck`: совместимость старых данных, новое время удаления, независимость от флага кошелька, повторное чтение и копирование — PASS.
- `check_bygram_spy_retention.py` — 16 сценариев; `check_bygram_settings_fixes.py` — 55 контрактов; MD3/геометрия, профиль (23 JVM-граничных проверки), заголовки и публичные ссылки — PASS.
- Android Java-компиляция Full Debug — PASS. Итоговый APK и отправка в Telegram фиксируются в docs/build.md.
- iOS: каталог локализации обновлён и воспроизводится генератором; проверка границ Postbox проходит. Добавлены XCTest для сохранения настроек, кодека времени удаления и формы фона кнопки аватара. Сборка, Swift typecheck, XCTest и запись кадров не выполнялись: Windows без Xcode/Apple SDK.
- ADB не видит устройств. Остаётся проверить на устройствах светлую/тёмную темы, большие шрифты, альбомы и медиа, повторное удаление после новых сообщений, перезапуск, GIF и возвращение из настроек. Визуальная корректность этими исходными проверками не подтверждается.

Новые строки en/ru/uk находятся в локальных XML Android и JSON-каталогах iOS. Публичный репозиторий переводов этим изменением не публиковался; перед следующим импортом публичного каталога нужно включить туда новые ключи.

Финальная проверка дополнена: Android повторно проверяет поколение ответа фона и переключатель показа чужих фонов; при возврате из настроек удаляется устаревшее смещение скрытого поиска. Для якоря-служебного сообщения уведомление добавляется в служебную плашку и TalkBack.

Цветной профиль с белым именем использует тёмную подложку изображения; обычный профиль сохраняет подложку текущей темы. Это согласовано с режимом белого имени `peerColor != null`.
