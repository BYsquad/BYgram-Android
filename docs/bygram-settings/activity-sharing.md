# Система активности

Клиент публикует и показывает активность выбранных собеседников. Клиентская точка входа — `BygramActivityController`, экран — `ActivitySharingSettingsActivity`, сервер — `server/activity-api`.

Открытый профиль обновляет видимую активность каждые 7 секунд. Карточка появляется и исчезает без повторного входа в профиль; временная ошибка сети не очищает последнее успешно полученное состояние.

## Возможности

Публикуются три взаимоисключающих состояния:

| Код | Маска | Текст |
|---|---:|---|
| `ACTIVITY_DIALOGS` | `1` | «Смотрит список чатов» |
| `ACTIVITY_PROFILE` | `2` | «Сидит в профиле у …» |
| `ACTIVITY_CHAT` | `4` | «В чате с …» |

Активность отображается:

- в заголовке личного чата;
- в профиле пользователя под блоком музыки;
- вместо превью последнего сообщения в строке личного диалога (системный typing-status имеет приоритет).

`ActivityInfo.text()` возвращает готовую локализованную фразу. Заголовок чата и профиль показывают её без дополнительного префикса «В чате с». В списке диалогов активность не имеет Telegram `printingStringType`: отсутствие типа следует трактовать как `-1`, не распаковывая `null` в `int`.

Когда в профиле показана только карточка активности без музыки, её измеренная высота остаётся 56 dp, а резерв заголовка уменьшается на 24 dp: стандартный верхний отступ следующей секции уже создаёт промежуток под карточкой. Это сохраняет небольшой одинаковый визуальный промежуток над карточкой и под ней.

Музыка и активность сворачиваются вместе с заголовком профиля: `ProfileMusicView` сжимает карточки по высоте и гасит весь слой по той же кривой, что фон кнопок `ProfileActionsView`. Слой включает иконки, поэтому после исчезновения карточки иконка активности не остаётся на экране.

Если активность приходит после открытия профиля, `ProfileActivity` меняет высоту заголовка и смещает первую строку списка на ту же величину. Иначе список сохраняет старую координату строки, а аватар ошибочно переходит в состояние частично свёрнутой шапки (эффект слияния с вырезом экрана). Во время анимации открытия новая высота учитывается в её конечном положении.

`DialogsActivity`, `ProfileActivity` и `ChatActivity` сообщают controller текущее состояние. Controller хранит одно состояние на Telegram account, отправляет heartbeat раз в 7 секунд и очищает совпадающее состояние при закрытии экрана. Серверный TTL — 60 секунд.

## Локальные действия в общих группах

В личном облачном чате клиент может показать свежее действие собеседника в общей группе. Сначала показывается действие в самом личном чате, затем действие из общей группы, затем доступная активность BYgram и штатный статус. Источник — обновления Telegram; наблюдения не отправляются на сервер BYgram и не сохраняются на диск.

## Просмотры профиля

Можно включить просмотры профиля отдельно для каждого аккаунта. Экран показывает недавних посетителей, время визита и новые записи. Если сервер требует подтверждения устройства, приложение предлагает войти через Telegram в браузере. Настройка активности и разрешения её получателей работают отдельно.

## Модель приватности

Доступ закрыт по умолчанию. Для каждого выбранного пользователя локально хранится отдельная битовая маска разрешений:

```json
{
  "123456789": 5,
  "987654321": 2
}
```

Ключ `bygram_activity_viewers_<account>` привязан к индексу Telegram account. Значение `5` разрешает список чатов и чат, значение `2` — только профили. Общий переключатель хранится в `bygram_activity_enabled_<account>`.

Старый JSON-массив viewer ID читается как разрешение `ACTIVITY_CHAT` (`4`). Это намеренно не открывает новым категориям доступ без согласия пользователя. При первом изменении настроек значение сохраняется в новом JSON-формате.

Экран настроек показывает выбранных пользователей и три переключателя под каждым. Новый пользователь получает только прежнее разрешение «в чате»; остальные категории включаются явно. Маска `0` удаляет пользователя из ACL.

После любого изменения ACL клиент сохраняет dirty-флаг, ждёт подтверждение `ok` от сервера и повторяет замену при ошибке сети. Запросы сериализованы, поэтому старый ответ не может перезаписать более новое изменение. Пока dirty-флаг не подтверждён, heartbeat активности не публикуется.

При первом запросе клиент создаёт сессию с ключом устройства. Дальше запросы используют токен сессии, а при истечении токена клиент обновляет его. Если сервер требует подтверждения аккаунта, приложение открывает страницу входа Telegram в браузере.

## API

Authenticated requests используют bearer token, timestamp, UUID nonce и подпись ключом привязанного устройства.

### `update`

Обновляет текущую активность владельца:

```json
{
  "action": "update",
  "activity_type": 2,
  "peer_id": 123456789,
  "peer_name": "@example"
}
```

Для типа `1` target не требуется. Старые клиенты могут передать `viewers`; сервер трактует их как маску `4`.

### `viewers`

Атомарно заменяет ACL владельца:

```json
{
  "action": "viewers",
  "viewers": [
    { "user_id": 123456789, "permissions": 5 }
  ]
}
```

Максимум 200 пользователей. Сервер отбрасывает неизвестные биты и записи с нулевой маской.

### `activity_get` и `activities`

`activity_get(owner_id)` используется заголовком чата и профилем. `activities(owner_ids[])` пакетно обслуживает строки списка чатов. В обоих случаях SQL возвращает состояние только при выполнении условия:

```sql
(activity_viewers.permissions & chat_activity.activity_type) <> 0
```

Клиентский batch-кеш живёт 7 секунд и объединяет запросы, созданные строками списка в течение 150 мс. Открытые личный чат и профиль также опрашивают активность каждые 7 секунд.

Старое действие `get` оставлено совместимым и возвращает только тип `ACTIVITY_CHAT`, поэтому старый APK не подпишет профильную активность как нахождение в чате.

## База данных и миграция

Миграция: `server/activity-api/migrations/20260916_activity_privacy.php`.

Для существующей базы также выполните `server/activity-api/migrations/20260919_activity_peer_kind.php` до публикации текущего `index.php`: запросы `update`, `activity_get` и `activities` используют колонку `chat_activity.peer_kind`. Если колонка отсутствует, API возвращает 503 на этих действиях.

- `chat_activity.activity_type TINYINT UNSIGNED`, default `4`;
- `chat_activity.peer_id` допускает `NULL` для списка чатов;
- `chat_activity.peer_kind TINYINT UNSIGNED`, default `0`;
- `activity_viewers.permissions TINYINT UNSIGNED`, default `4`.

Default `4` сохраняет прежнюю семантику уже существующего ACL. Миграция идемпотентна.

## Проверка

1. Выполнить миграцию и `$env:BYGRAM_TEST_LOCAL='1'; php -d zend.assertions=1 -d assert.exception=1 server/activity-api/self-test.php`: тест создаёт отдельную временную локальную MySQL-базу, применяет `schema.sql` и удаляет базу при завершении.
2. Собрать клиент и установить его на тестовые устройства.
3. На тестовых аккаунтах A и B выбрать B на A и отдельно проверить каждую из трёх масок.
4. Убедиться, что пользователь без ACL и категория без разрешения ничего не получают через `get` и `activities`.
5. Проверить исчезновение состояния после закрытия экрана и не позже 60 секунд при аварийном завершении клиента.
6. Проверить, что после выключения отправки очищается опубликованная активность.
7. Отключить сеть, отозвать viewer, вернуть сеть и убедиться, что heartbeat не возобновился до подтверждённой замены ACL.
8. Для каждого типа активности открыть личный чат с владельцем и проверить, что заголовок содержит ровно одну готовую фразу; для профиля не должно быть «В чате с Сидит в профиле у…».
9. Открыть список диалогов, дождаться ответа `activities` с видимой активностью, затем дождаться ответа без активности: строка должна обновиться без `NullPointerException`.
10. В профиле без музыки проверить, что видимый промежуток над карточкой активности и под ней одинаково мал.
11. Прокрутить профиль с карточкой активности, с музыкой и с обеими карточками: они должны сжиматься и исчезать вместе с кнопками; иконка активности не должна оставаться после фона и текста.
12. Открыть профиль с кастомной музыкой, дождаться позднего появления активности и проверить, что аватар остаётся круглым и не тянется к вырезу экрана; повторить после прокрутки и возврата к началу.

Не используйте личные чаты для production-теста: target name кратковременно передаётся backend BYgram.
