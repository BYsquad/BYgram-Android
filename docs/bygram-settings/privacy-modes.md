# Ghost Mode и Spy Mode

24.10.2026: [автопубликация фона, индикатор загрузки и уведомления об удалениях](spy-notifications-and-background-2026-10-24.md).

## Ghost Mode

`GHOST_ENABLED` — master. Поднастройки сохраняются при выключении master, но predicates возвращают блокировку только при включённом master.

| Опция | Контракт | Основные потребители |
|---|---|---|
| Не читать сообщения | `shouldBlockReadReceipts()` | cloud/secret receipts, content, mentions, reactions, live location |
| Не читать истории | `shouldBlockStoryReads()` | `StoriesController` |
| Не показывать online | `shouldBlockOnline()` | `MessagesController` online timer |
| Не показывать typing | `shouldBlockTyping()` | sending action и bot callback |
| Читать при действиях | `shouldReadOnActions()` + `withReadReceipt()` | send/reaction и явный mark-as-read |

`withReadReceipt()` использует `ThreadLocal` и снимает override в `finally`. Новая отправка receipt должна использовать общий predicate; не читайте raw preference в каждом caller.

Ghost блокирует только сетевые receipts. Локальные счётчики сообщений, mentions, reactions, live locations и stories обновляются как прочитанные единообразно. «Читать при действиях» временно разрешает receipt и для cloud-, и для secret chats; encrypted path передаёт текущую серверную дату.

Toggle master или `GHOST_NO_ONLINE` вызывает `updateTimerProc()`, чтобы новое online-состояние применилось без перезапуска.

## Spy Mode

### Сохранение удалённых сообщений

`SPY_SAVE_DELETED` не даёт физически удалить входящее сообщение и ставит custom message flag. Значок удаления отображается в строке времени перед галочками доставки. Покрыты обычные сообщения, channel delete, push delete, clear history и secret-chat random IDs/flush history. Данные остаются в SQLite и не входят в `clearSpyData()`.

При повторном локальном удалении сообщения с этим флагом `MessagesController.deleteMessages()` переводит его в ветку физического удаления и удаляет из истории.

18.10.2026: добавлен `SPY_SAVE_OWN_DELETED` — «Сохранять свои сообщения при удалении мной», по умолчанию выключен. Работает вместе с `SPY_SAVE_DELETED`, входит в экспорт/сброс. При выключенной опции отдельно выбранные свои сообщения удаляются физически, запрос удаления на сервер всё равно отправляется. Входящие сохраняются как прежде.

Удаление всего диалога при включённом `SPY_SAVE_DELETED` сохраняет входящие и собственные сообщения независимо от `SPY_SAVE_OWN_DELETED`, в том числе если чат содержит только исходящие. Диалог остаётся в текущем списке, включая период Undo; история получает отметки Spy. Переключатель собственных сообщений продолжает действовать для удаления отдельных сообщений и очистки истории. Если вся оставшаяся история уже помечена Spy, повторное удаление удаляет диалог и локальную историю. Новые непомеченные сообщения снова делают историю обычной. `onlyHistory=2` (очистка кеша) и `3` (служебное исключение диалога) сохраняют штатное поведение.

## Скрытые и запароленные чаты

Обе функции доступны в Lite и Full и используют локальное хранилище `BygramChatPrivacy` отдельно для каждого Telegram account. Коды и пароли проверяются по PBKDF2-HMAC-SHA1 с индивидуальной солью; в экспорте BYgram их нет, сброс настроек их удаляет.

«Скрытые чаты» показывают уже выбранные личные чаты, группы и каналы стандартными строками с аватаром и последним сообщением; значок «+» справа в заголовке открывает обычный список диалогов для добавления. Числовой код длиной от четырёх цифр вводится в поиск списка чатов: перед вкладкой «Чаты» появляется вкладка «Скрытые чаты», она выбирается автоматически и показывает скрытые диалоги прямо под строкой поиска. При закрытии поиска вкладка и её содержимое исчезают; последующий обычный поиск снова показывает результаты. Код можно изменить после ввода старого. Обычный список и локальные результаты поиска исключают скрытые диалоги; открытие через другую навигацию блокируется. Уведомления показывают «Откройте, чтобы прочитать» и открывают список чатов.

«Запароленные чаты» также показывают выбранные диалоги стандартными строками с аватаром и последним сообщением; новые добавляются значком «+» в заголовке. Каждый диалог получает свой пароль длиной от четырёх символов. Для изменения или снятия пароля нужен старый пароль. Навигация запрашивает пароль до вызова `ChatActivity.onFragmentCreate()`; сам экран чата дополнительно отклоняет открытие без одноразового разрешения. Предпросмотр в обычном списке чатов заменяется красным «Скрыто 🔒». Уведомления скрывают текст и вложения так же, как для скрытых чатов: вместо них отображается «Откройте, чтобы прочитать».

## Сохранение медиа

`PhotoViewer` и контекстное меню `ChatActivity` показывают сохранение доступных локально фото, видео, кружков и файлов независимо от запрета пересылки (`noforwards`). Для купленного за звёзды медиа это действует после раскрытия полной версии; размытое превью до покупки и исчезающие медиа остаются недоступными.

Для сообщений из чатов с запретом пересылки или с флагом `noforwards` действие «Переслать» отправляет новую копию через `SendMessagesHelper`, а не серверный `messages.forwardMessages`. Фото и документы сначала догружаются локально и загружаются заново; это необходимо, потому что Telegram допускает повторную отправку по ссылке только для незащищённого медиа. У копии нет исходной отметки автора пересылки. Обычные сообщения используют штатный путь; серверные права на отправку в целевой чат продолжают действовать.

### История правок

Перед применением cloud edit сохраняются предыдущие text/entities/date, media и локальный attachPath. Медиа сериализуется целиком в TL, включая cached_page (InstantPage), фото, документы и их превью; изменение только медиа также создаёт ревизию. Одинаковая последняя версия по тексту, entities и media пропускается, максимум — 20 ревизий на message key. Контекстное меню показывает историю в обратном порядке штатными ChatMessageCell: форматированный текст, подписи, вложения и Instant View. Instant View открывает сохранённую страницу, просмотр фото/видео — выбранную ревизию без подмешивания текущих сообщений чата.

Старые текстовые записи читаются без миграции; отсутствующие ранее медиа восстановить задним числом нельзя. История хранит метаданные вложений, а не отдельную архивную копию файлов: после очистки кеша загрузка старого вложения зависит от доступности файла и его Telegram file reference. У карточек локальные ID, чтобы воспроизведение разных версий не смешивалось с текущим сообщением; `ArticleViewer.openSnapshot()` не обновляет старую InstantPage из сети. Проверки регрессий: `Tools/check_bygram_settings_fixes.py`, `Tools/BygramEditMediaCheck.java` (команды в [testing.md](testing.md)).

90-дневный prune запускается при старте приложения и удаляет каждую просроченную ревизию, даже если у сообщения есть более свежая история.

### Дата прочтения

`rememberReadDate()` обрабатывает outbox read updates для cloud и channel dialogs. Диапазоны ограничены 256 элементами и 90 днями.

Первый update получает предыдущий `outbox max` из `MessagesController`/storage и сохраняет весь новый диапазон `previousMax + 1 … maxMessageId`. Старая история до baseline не получает новую дату.

### Последний online

`rememberLastOnline()` принимает наблюдаемые status/read update timestamps. `getLastOnline()` не возвращает значения старше 90 дней; `pruneSpyData()` удаляет их при старте приложения.

### Очистка

`clearSpyData()` удаляет только ключи `bygram_edit_*`, `bygram_read_*`, `bygram_online_*`. Сохранённые удалённые сообщения в SQLite остаются; UI явно говорит «история правок, чтения и онлайн».

## Обязательная матрица тестов

| Сценарий | Ghost | Spy |
|---|---|---|
| Личный cloud chat | read/typing/online/action override | delete/edit/read date/online |
| Группа и форум | read/mention/reaction | delete/edit/read date |
| Channel | read | delete/read date |
| Secret chat | receipt/typing | random delete/flush/TTL |
| Stories | story receipt | — |
| Bot callback | action override/typing | — |
| Background/foreground | online | prune/persistence |

После теста возвращайте пользовательские switches и не подтверждайте destructive clear на реальном аккаунте.
