# Кастомизация

## Общие

### Иконка приложения

`AppIconsSelectorCell` переключает manifest alias через `LauncherIconController`. В кастомизации доступны только `DEFAULT` (BYgram, `logo-new.png`) и `AQUA` (стандартная иконка Telegram). `DEFAULT` включён в manifest для новых установок; прежний alias `VINTAGE` мигрирует на `DEFAULT` при запуске. Выбранный пользователем Telegram сохраняется. Предпросмотр и оба launcher-поля `AQUA` используют отдельный `telegram_logo.png` с оригинальным синим логотипом: адаптивный `ic_launcher` получает красный фон BYgram и для Telegram не подходит. Все Android-вхождения логотипа BYgram (настройки, QR, условия использования, приглашение, launcher aliases) используют `bygram_logo_new`, совпадающий с корневым `logo-new.png`. Это component state, а не ключ `BygramConfig`; reset явно вызывает `LauncherIconController.setIcon(DEFAULT)`.

### Заставка при запуске Android

На Android 12+ системная заставка использует статичный логотип BYgram (`bygram_splash` → `bygram_logo_new`) вместо анимации Telegram. Ресурс задан в светлой (`values-v31`) и тёмной (`values-night`) стартовых темах; отступы 25% сохраняют логотип внутри круглой маски системной заставки. Выбор иконки рабочего стола не меняет эту заставку. На Android 11 и ниже стартовый фон остаётся прежним.

### Фильтр Zalgo

`FILTER_ZALGO` включает `BygramTextUtils.filterZalgo()` из `Emoji.replaceEmoji()`. Алгоритм ограничивает combining marks и пересчитывает offsets/lengths `MessageEntity`.

Проверка после изменения:

```powershell
$checkDir = Join-Path $env:TEMP 'bygram-text-check'
New-Item -ItemType Directory -Force -Path $checkDir | Out-Null
javac -d $checkDir TMessagesProj/src/main/java/org/telegram/messenger/BygramTextUtils.java Tools/BygramTextCheck.java
java -cp $checkDir BygramTextCheck
```

### Material 3

| Ключ | Потребители | Граница |
|---|---|---|
| `MD3_LOADING` | `CircularProgressDrawable`, `RadialProgressView` | progress/loading indicators |
| `MD3_SLIDERS` | `SeekBarView` | только простой one-way slider без buffer/timestamps/min-value |
| `MD3_SWITCHES` | общий `Switch` | BYgram/Telegram switch component |

UI-группа раскрывается без отдельного persisted expanded state; счётчик показывает число включённых опций.
Общий `Switch` в режиме MD3 содержит официальный `MaterialSwitch` из уже установленной библиотеки Google Material Components. Геометрию ручки/трека и анимации переключения/нажатия выполняет библиотека; ручной имитации MD3 нет. Цвета трека и ручки берутся из заданных клиентом Telegram ключей (`setColors` и `ResourcesProvider`), обводка — из `switchTrackBlueThumb`. Палитра Material/динамические цвета Android не подменяют тему клиента. Штатные строки выделяют 52 × 32 dp; в ограниченном контейнере компонент масштабируется целиком. Неанимированная привязка строк, существующие иконки, круговое раскрытие цвета и единый accessibility node сохранены.

`SeekBarView` использует геометрию `Widget.Material3.Slider` установленной библиотеки Google Material Components без ручной подмены толщины трека, размеров ручки и скрытия стоп-маркеров/делений. Индикаторы загрузки уже используют официальный `LoadingIndicator`; их анимация сохранена.

Источники сверки: [Material Switch](https://github.com/material-components/material-components-android/blob/master/docs/components/Switch.md), [официальные стили Slider](https://github.com/material-components/material-components-android/blob/master/lib/java/com/google/android/material/slider/res/values/styles.xml). Эти три опции меняют конкретные компоненты, а не переводят все экраны Telegram на Material 3.

### Углы аватаров

`AVATAR_CORNERS`, 0…28 dp: 0 — square, 28 — circle. Значение ограничивается UI и применяется общим `ImageReceiver`, включая форумные avatars. Новый special avatar shape не должен обходить этот контракт без явного исключения в UI.

Обводка реакций под сообщениями также использует `BygramConfig.avatarRadius(height)`: при 0 она квадратная, при увеличении настройки её углы скругляются вместе с аватарами.

Одинаковая геометрия применяется к фону реакции и эффекту поверх него. `AvatarsDrawable` и `AvatarsListDrawable` (участники опросов) используют форму аватара для масок перекрытия, обводок и кольца историй. В стеклянном заголовке чата левый край блока возле аватара следует настройке; при поиске, контекстных действиях и отсутствии аватара плавно возвращается к обычной форме. Правая сторона блока сохраняет штатное скругление.

### Поля ввода BYgram

PIN скрытых чатов, пароли в настройках и при открытии защищённого чата, а также редактор статусов используют общий `EditTextBoldCursor`: фон и цвета из темы, скругление 12 dp, рамка 1 dp (2 dp при фокусе), внутренние отступы 16 dp и высота не менее 56 dp. Контейнер добавляет боковые отступы 24 dp. Высота растёт при увеличении шрифта. Типы парольного ввода, проверки PIN/пароля и лимит статуса 64 символа сохранены.

### Liquid Glass

Дополнительная маска областей BYgram удалена. Штатный флаг Telegram `LiteMode.FLAG_LIQUID_GLASS` доступен в «Настройки чата → Анимации → Анимации в чатах» на поддерживаемых устройствах и управляет эффектом во всех штатных потребителях.

## Профиль

### Кастомный статус печати

В Full раздел «Настройки BYgram → Кастомизация» содержит экран фраз для действий в личном чате: набор текста, запись голоса, отправка файла/фото/видео/аудио, запись и отправка видеосообщения и игра. В Lite экран скрыт и `BygramTypingController` не публикует и не отображает статусы. Пустая фраза оставляет статус Telegram. Длина фразы ограничена 64 символами. Настройки хранятся отдельно для каждого Telegram account под ключами `bygram_custom_typing_<account>_<action>`, входят в экспорт и сброс.

Клиент публикует набор фраз через `typing_put` и читает фразы автора через `typing_get` только при наличии обычного Telegram typing action в личном диалоге. Поэтому обычный Telegram-клиент продолжает показывать стандартный статус, а BYgram подменяет его фразой. Сервер не получает список собеседников или текст сообщений. Результаты `typing_get` кэшируются на 7 секунд.

Поле `statuses` в ответе `typing_get` всегда должно быть JSON-объектом, в том числе для пустого набора и единственного действия `0`. PHP преобразует массив с числовым ключом `0` в JSON-массив; Android-клиент читает поле через `optJSONObject` и не покажет фразу из такого ответа. При сохранении `typing_put` также кодируйте фразы как JSON-объект.

В Full без активной лицензии первую публикацию владелец подтверждает через ссылку бота (`typing_register` и `/start typing_...`). Бот проверяет Telegram ID, полученный от Telegram, и привязывает публичный ключ Android Keystore. После подтверждения пользователь повторно нажимает «Опубликовать статусы».

В Full уже привязанное устройство с активной лицензией публикует статусы сразу, используя тот же ключ Android Keystore: отдельное подтверждение статусов через бота не требуется. Сервер принимает ключ только пока устройство не отозвано и лицензия активна. Если Full ещё не активирован, остаётся независимая привязка статусов через бота. `typing_put` проверяет подпись, timestamp и одноразовый nonce.

После успешного ответа `typing_put` экран показывает подтверждение сохранения. При ошибке остаётся сообщение о неудачной публикации или запрос подтверждения через бота. Сохранение отдельной фразы также публикует обновлённый набор.

Перед развёртыванием PHP нужно применить `server/activity-api/migrations/20260923_typing_statuses.php` в контексте с настроенным `$pdo`; те же таблицы добавлены в `schema.sql` для новых установок.

### Значки рядом с именем

Админ панель выдаёт значок по Telegram ID и типу `user` или `chat` (канал, группа, супергруппа). Для чата принимаются положительный внутренний ID и Bot API ID с префиксом `-100` или `-`. Для пользователя используется `logo-new.png`, для ресурсов — `bygram-logo.png`. Публичный API `badges` возвращает назначенные ID, клиент кэширует результат 5 минут. Нажатие на значок открывает короткое уведомление внизу экрана. Старые записи пользовательских значков в `badges.json` читаются как BYgram-значок пользователя.

Уведомление значка использует Telegram Bulletin и текущий язык Telegram. В заголовке открытого чата значок добавляется после остальных правых иконок; обновление данных значков вызывает `updateInterfaces` и перерисовку заголовка, включая «Избранное», каналы и группы.

Клиент сохраняет полученные положительные назначения в локальном кеше и показывает их сразу при следующем запуске, затем обновляет с сервера в отдельной сетевой очереди. Для одного ID не создаётся повторный запрос, пока предыдущий выполняется; отрицательный ответ и сетевая ошибка перепроверяются через минуту. После ответа обновляются как пользовательские строки, так и строки каналов/групп в списке чатов.

### Музыка профиля

`CUSTOM_PROFILE_MUSIC` включает карточку `ProfileMusicView` отдельной строкой на обычном фоне профиля, над привязанным каналом (либо над сведениями, если канала нет). В контейнере аватара при этом остаётся только карточка активности. При выключении используется стандартная музыкальная плашка Telegram в заголовке; сохранённая музыка не меняется. Нажатие на карточку вызывает общий обработчик воспроизведения и открытия плеера. Поздняя загрузка или удаление музыки обновляет строку списка, не увеличивая заголовок.

Квадрат обложки кастомного плеера показывает миниатюру аудиодокумента, если Telegram сохранил встроенный арт. Для уже скачанного файла без миниатюры клиент читает встроенный арт локально через `AudioInfo` в фоновой очереди. При отсутствии обложки остаётся иконка музыки.

`getContentHeight()` уже возвращает пиксели. При расчёте высоты заголовка и положения панели действий повторно применять `dp()` к этому значению нельзя.

### ID и DC

`PROFILE_ID_MODE`:

- 0 — скрыто;
- 1 — Telegram API ID;
- 2 — Bot API ID (`-` для group, `-100` для supergroup/channel).

Mode применяется и при отображении, и при копировании. UI ограничивает индекс по размеру `BygramIdOptions`; новый mode требует обновить обе ветки профиля и массив строк.

Нажатие на блок ID/DC копирует только ID в выбранном формате и всегда показывает Telegram Bulletin «ID скопирован в буфер обмена», в том числе на Android с системной подсказкой буфера обмена.
