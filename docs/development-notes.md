# Примечания для разработчиков BYgram

Здесь фиксируются решения, которые нужно учитывать при изменении кастомных
функций и обновлении базы Telegram. Это действующие условия совместимости,
а не список незавершённых задач. При изменении решения обновляйте этот файл
вместе с кодом и проверками; для сохраняемых данных указывайте миграцию.

## Локальные параметры сообщений: Spy и кошелёк

Зафиксировано при обновлении до Telegram 13.0.2 (`f32ffee`), 14 октября 2026 года.
Реализация: [MessageCustomParamsHelper.java](../TMessagesProj/src/main/java/org/telegram/messenger/MessageCustomParamsHelper.java),
внутренний класс `Params_v1`.

| Бит | Маска | Назначение в BYgram |
|---|---|---|
| 14 (`FLAG_14`) | `16384` | `message.bygramDeleted`: сообщение сохранено режимом Spy после удаления |
| 15 (`FLAG_15`) | `32768` | `comment_encrypted_preparing`: подготовка шифрования комментария перевода Gram |

**За Spy оставлен бит 14, чтобы старые локальные данные читались без миграции.
Новое состояние кошелька читает и пишет бит 15.** В официальном Telegram
на базе `f32ffee` кошелёк использует бит 14, но в BYgram он уже был занят.
Это намеренное отличие от upstream, которое нельзя устранять простым
копированием официального serializer.

Оба признака независимы. В `isEmpty` учитываются оба; чтение и запись каждого
должны использовать одинаковую маску. После получения зашифрованного
комментария (`comment_encrypted=true`) старый локальный preparing не должен
снова включаться. Версия локального формата остаётся `1`.

При следующих обновлениях проверяйте назначения **всех** новых флагов
`Params_v1`, особенно бита 15. Не переносите существующий признак на другой
бит без миграции сохранённых данных: иначе после перезапуска изменится
смысл уже записанных сообщений. Эти биты относятся к локальным параметрам,
а не к сетевому TL-формату сообщений.

Проверка: [BygramMessageParamsCheck.java](../Tools/BygramMessageParamsCheck.java).
Она читает fixture формата BYgram 12.10.5, проверяет независимость флагов,
повторное чтение, копирование Spy и состояние после появления ciphertext.
Команда запуска приведена в [инструкции проверки](bygram-settings/testing.md).

## Идентификаторы действий и настроек

В [ChatActivity.java](../TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java)
`OPTION_SEND_MONEY=117` оставлен за Telegram. Ранее этот номер занимала
история редактирования BYgram. Текущее распределение:

| Константа | ID |
|---|---|
| `OPTION_BYGRAM_EDIT_HISTORY` | `1001` |
| `OPTION_BYGRAM_DETAILS` | `1002` |
| `OPTION_BYGRAM_SAVE` | `1003` |
| `OPTION_BYGRAM_REPEAT` | `1004` |
| `OPTION_BYGRAM_COPY_PHOTO` | `1005` |

Используйте именованные константы в построителях меню и обработчиках.
При добавлении upstream-действий проверяйте уникальность `OPTION_*`;
это проверяет [check_bygram_settings_fixes.py](../Tools/check_bygram_settings_fixes.py).
Диапазон `1001..1005` сам по себе не гарантирует отсутствия будущих коллизий.

В [SettingsActivity.java](../TMessagesProj/src/main/java/org/telegram/ui/SettingsActivity.java)
вход BYgram использует `BYGRAM_SETTINGS_ID=1000`. ID `24` остаётся за
настройками круглых видео Telegram, ID `25` — за кошельком Telegram.
ID меню чата и ID экрана настроек относятся к разным наборам действий.

## Другие решения при объединении с Telegram

- **QR-коды:** в [TelegramQRCodeWriter.java](../TMessagesProj/src/main/java/org/telegram/messenger/TelegramQRCodeWriter.java)
  переданный `centerDrawable` имеет приоритет. Без него используется логотип
  BYgram. Нельзя безусловно заменять центральное изображение: кошелёк
  передаёт собственный drawable.
- **Камера:** в [InstantCameraView.java](../TMessagesProj/src/main/java/org/telegram/ui/Components/InstantCameraView.java)
  сохранено поле zoom BYgram вместе с новыми полями синхронизации
  переключения камеры Telegram. При обновлении учитывайте обе группы полей.
- **Биометрия:** старый внутренний `PasscodeView.FingerprintDialog` удалён
  вслед за upstream. Не возвращайте его ради прежних строк брендинга;
  актуальная реализация блокировки находится в обновлённом `PasscodeView`.
- **Активность профиля:** текущий интервал обновления — 7 секунд.
  Высота карточки учитывается через `getHeaderHeight()` и общий
  `adjustHeaderForMusicChange()`. Старые проверки на 20 секунд и прямое
  изменение `extraHeight` не описывают текущую реализацию.
- **Liquid Glass:** используется штатная настройка Telegram.
  Отдельные BYgram placements удалены; не восстанавливайте их по старым
  тестам или оставшимся названиям ресурсов.
- **Локализация:** при объединении строк сохраняйте новые предупреждения
  Telegram, в частности об удалении резервных копий кошелька при выходе.
  Замена названия приложения не должна удалять смысл предупреждения.
- **Идентичность приложения:** основной package — `com.bygram.mobile`.
  При обновлении Gradle сохраняйте разделение Lite/Full и настройки подписи.
  Номера версии обновляются отдельно от этих условий совместимости.

## Следующее обновление базы

Текущая база: `0aae959806c57be8ad457980f2a5c6277ff18635` (Telegram 13.0.3).
С 22.10.2026 история BYgram связана с upstream: уже перенесённая база
`f32ffee` записана отдельным `ours` merge, затем объединён полный upstream
диапазон из 14 коммитов. Следующие обновления выполняйте обычным merge,
сохраняя промежуточные коммиты. Подробности — в
[отчёте 13.0.3](bygram-settings/telegram-13.0.3-upgrade.md).
Получайте submodules на ревизиях целевого коммита, включая уже существующие:
при обновлении до 13.0.2 изменился также `tlottie`.
Если общей истории с upstream нет, базу трёхстороннего объединения нужно
указывать явно. После объединения сверяйте gitlinks с целевым деревом.

История переноса и выполненные проверки находятся в
[отчёте обновления до 13.0.2](bygram-settings/telegram-13.0.2-upgrade.md).
Успешная компиляция и статические контракты не заменяют проверки Ghost,
Spy, защищённых чатов, камеры и серверных функций на устройстве.

В 13.0.3 новый аудиорекордер V2 при остановке записи также обязан применять
`BygramConfig.hapticFeedback()`, как legacy-рекордер. ID 26 в SettingsActivity
принадлежит настройкам аудиорекордера; вход BYgram сохраняет ID 1000.

## Исходники Telegram для iOS

Официальная база Telegram-iOS размещена отдельно от Android BYgram в `C:\project\BYgram-ios` и загружается вместе с зафиксированными upstream подмодулями командой `git clone --recurse-submodules https://github.com/TelegramMessenger/Telegram-iOS.git C:\project\BYgram-ios`. Этот checkout является исходниками Telegram без патчей BYgram; сборка в рамках загрузки не выполняется.

## Android: реклама и профиль, 17.10.2026

- `MessagesController.isSponsoredDisabled()` всегда возвращает `true`: реклама отключена для всех аккаунтов, независимо от Premium и серверного `sponsored_enabled`. Общий загрузчик отсекает также кеш рекламы каналов/ботов; поиск не запрашивает sponsored peers; `VideoAds` не загружает и не планирует рекламу из кеша. Пользовательские сообщения и контент сайтов не фильтруются.
- Логотип Android заменён на `logo-new.png`; выбор Telegram использует отдельный синий ресурс, обходящий красный адаптивный фон BYgram.
- Кастомная музыка — строка списка над каналом; высота заголовка учитывает только оставшуюся активность или стандартную плашку. Подтверждение копирования ID использует `createSimpleBulletin`, поскольку `createCopyBulletin` возвращает пустое уведомление на новых Android.
- Статические проверки: `Tools/check_bygram_no_ads.py`, `Tools/check_bygram_profile_activity.py`, `Tools/check_bygram_md3_geometry.py`. Требуется smoke-проверка профиля на устройстве: с каналом и без, поздняя загрузка/удаление музыки, сворачивание аватара, светлая/тёмная тема, копирование ID и выбор обеих иконок.

Проверка 17.10.2026: `-PBYGRAM_EDITION=full :TMessagesProj_App:compileAfatDebugJavaWithJavac` — успешно; четыре статические проверки (реклама, профиль, MD3/иконки, 44 контракта настроек) — успешно. Лог: `output/build-android-profile-final-2026-10-17.log`. APK не пересобирался; подключённых Android-устройств нет.
