# Сравнение систем плагинов BYgram и exteraGram

12 ноября 2026 года

**exteraGram шире как платформа для авторов плагинов.** Его SDK даёт готовые перехваты Telegram, отправку и редактирование сообщений и медиа, больше точек встраивания в интерфейс, зависимости и отладку на устройстве. Elyx и подключаемые репозитории позволяют развивать большие плагины и распространять их независимо от команды клиента.

**BYgram подробнее управляет жизненным циклом установленного пакета.** В текущем коде есть согласие на запуск конкретного пакета, привязка доступа SDK к авторизации аккаунта, проверка подписи и ключа автора, отложенное обновление с откатом, отзыв по SHA-256 и автоматическое восстановление. По ширине публичного SDK BYgram уступает. По возможностям низкоуровневого расширения обе системы дают доступ к Java и хукам ART, а масштаб применимости зависит от конкретных сборок и устройств.

## Распространение, контроль и восстановление

| Область | BYgram | exteraGram |
| --- | --- | --- |
| Публикация | В текущем серверном коде новый релиз подаётся из публичного GitHub Release с одним подписанным `.byplugin`. Модератор проверяет точный пакет. Следующая версия проходит новую модерацию. | Пользователь подключает публичный Telegram-канал или HTTPS-репозиторий с `extera-plugins.json`. Канал публикует документы, Git-источник может быть на GitHub или другом хостинге. Новая версия появляется через источник. [Репозитории](https://plugins.exteragram.app/docs/plugin-repositories) |
| Доверие к пакету | SHA-256 и размер из каталога, опциональная подпись локального пакета, проверка целостности содержимого и закрепление ключа подписанного автора при обновлении. Локальная установка требует подтверждения. Установленный пакет выключен до отдельного согласия на исполнение. | Для Git-источника сверяются размер, SHA-256, ID и версия. Установка требует разрешить неизвестные источники, окно установки показывает результат анализа безопасности. Сопоставимая подпись автора и закрепление ключа в изученном справочнике не описаны. [Репозитории](https://plugins.exteragram.app/docs/plugin-repositories) |
| Обновление и отзыв | Совместимое обновление применяется при холодном старте, новая версия остаётся выключенной до согласия. Явный откат возвращает предыдущий пакет и снимок настроек. Клиент блокирует отозванный SHA-256 после получения списка отзывов. | Git-каталог предлагает обновление по версии, Telegram-канал использует свежую публикацию или правку сообщения. Сопоставимый откат пакета вместе с настройками и централизованный отзыв по SHA-256 в изученном справочнике не описаны. [Репозитории](https://plugins.exteragram.app/docs/plugin-repositories) |
| Сбой плагина | Таймауты и карантин SDK, резервный реестр, маркеры активации и запуска. При прерванной активации или ошибке восстановления клиент входит в безопасный режим. Экран восстановления открывается в отдельном процессе. | Документированы автоматическое снятие хуков при выгрузке, логирование и safe mode при несовместимой версии приложения. Сопоставимый сценарий восстановления после падения плагина публичным справочником не подтверждён. [Введение](https://plugins.exteragram.app/docs) · [Хуки](https://plugins.exteragram.app/docs/xposed-hooking) · [Логи](https://plugins.exteragram.app/docs/logging) |

В BYgram capabilities и аккаунтные разрешения действуют на границе штатного SDK. Доверенный Python/Java работает с правами процесса клиента. Модерация, RSA-подпись и закрепление ключа управляют происхождением и целостностью пакета. Изоляции исполнения они не обеспечивают. Для прямого Java и синхронных raw hooks действуют ограничения потока вызываемого метода, а зависший авторский поток может оставаться до перезапуска. [SDK v1](sdk-v1.md#границы-доступа-sdk) · [PluginManager.java](../../TMessagesProj/src/plugins/java/org/telegram/messenger/plugins/PluginManager.java) · [Сервер каталога](../../server/activity-api/plugin-catalog.php)

## Масштаб на практических сценариях

- **Тема, кнопка в чате, настройка на аккаунт или ручное преобразование черновика.** Для этих сценариев у BYgram есть готовый SDK и примеры. Переопределение цветов и подтверждаемый предпросмотр черновика дают автору штатные точки интеграции с клиентом. [Примеры BYgram](examples) · [SDK v1](sdk-v1.md)
- **Переводчик, срабатывающий при отправке, действие над выбранным сообщением или плагин для медиа.** В exteraGram это строится на публичных hook, menu и client API. В BYgram для сопоставимого автоматического перехвата, пункта в контексте сообщения или отправки медиа понадобятся внутренние классы Telegram и в ряде случаев хуки с проверкой на целевых сборках. [SDK BYgram](sdk-v1.md) · [BasePlugin](https://plugins.exteragram.app/docs/plugin-class) · [Client Utilities](https://plugins.exteragram.app/docs/client-utils)
- **Многофайловый продукт с переводами, библиотеками и частыми релизами.** Оба формата поддерживают Python-модули. Elyx добавляет собственные контракты для ресурсов, переводов и зависимостей, синхронизацию с устройством и независимый канал публикации. У BYgram внешний проект может поставлять свои Python-модули внутри архива, а публичный каталог работает через централизованную модерацию. [Руководство BYgram](README.md) · [Elyx](https://plugins.exteragram.app/docs/elyx) · [Репозитории exteraGram](https://plugins.exteragram.app/docs/plugin-repositories)
- **Масштаб распространения.** В публичном индексе BYgram на дату отчёта шесть примеров SDK. У всех шести архивов сверены размер, SHA-256 и manifest. Ни в одном из этих пакетов нет `signature.json`. Публичный список отзыва пуст. Пример хуков привязан к BYgram build 72379 / Telegram build 7237, поэтому наличие в индексе само по себе не означает совместимость с 13.2.1. exteraGram документирует восемь категорий и подключаемые источники. Общее число сторонних плагинов, установок и активных авторов из этих данных определить нельзя. [Индекс BYgram](https://byxarek.site/TEST-PROJECT/BYgram/plugins/index.json) · [Список отзыва](https://byxarek.site/TEST-PROJECT/BYgram/plugins/revoked.json) · [Manifest hook-примера](examples/hooks/manifest.json) · [Категории exteraGram](https://plugins.exteragram.app/docs/plugin-class)

## Что проверено

- BYgram исследован по Android-репозиторию `BYgram-mobile`, включая текущие незакоммиченные изменения поверх `856c8fb77`. Проверены клиентский и серверный код, локальная документация и общедоступный HTTPS-каталог. Правило подписи для новых релизов и процедура отзыва подтверждены в локальном коде. Работу серверной модерации на production и отзыв установленного пакета в ходе этого сравнения не проверял.
- `python Tools/check_plugins.py` завершился с кодом 0. Проверки включают подпись и смену ключа, прерывание записи, обновление и откат, реестр отзывов, валидацию ZIP и манифестов, а также примеры SDK. Проверки Python-адаптера с подставным Java-мостом не измеряют работу ART. Проектная матрица фиксирует прогон восстановления на Android API 37 x86_64 в Debug 13.2.1. Для текущего backend диапазон API 24–37 на arm64/x86_64 задаёт допуск к пробе, а покрытие всех устройств требует отдельных прогонов. [Проверки и выпуск](testing-and-release.md) · [SDK v1](sdk-v1.md#hooks-и-восстановление)
- exteraGram исследован по опубликованной документации. Введение указывает SDK 1.4.4.3, Python 3.11 и рекомендует exteraGram 12.5.1+. Отдельная страница multi-account требует SDK 1.4.5.0+ для новых account helpers, поэтому для каждого API применим минимум из его собственного раздела. APK exteraGram и сравнительная производительность не проверялись. [Введение](https://plugins.exteragram.app/docs) · [Multi-account](https://plugins.exteragram.app/docs/multi-account)
