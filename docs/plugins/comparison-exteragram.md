# Плагины BYgram Full и exteraGram

Этот отчёт фиксирует состояние до доработки. Текущие контракты и оставшиеся отличия описаны в [руководстве по переносу](exteragram-port.md).

Срез от 14 ноября 2026 года по исходникам BYgram Android Full на `7ab64b775b32840eb1d67b35630f13be4ae30a85` и публичной документации exteraGram. Во введении exteraGram указаны Python 3.11 и SDK 1.4.4.3. Для новых multi-account helpers документация указывает SDK 1.4.5.0+, а для Intent API — приложение 12.6.4+. В BYgram Full используется Python 3.11. В Lite движок отсутствует. [Введение exteraGram](https://plugins.exteragram.app/docs) · [Multi-account](https://plugins.exteragram.app/docs/multi-account) · [Intents](https://plugins.exteragram.app/docs/intents) · [Сборка BYgram](../../TMessagesProj/build.gradle)

BYgram уже импортирует однофайловые `.plugin` и структурированные Elyx-плагины, перехватывает события Telegram, предоставляет настройки, меню, диалоги, отправку и редактирование сообщений. Основные оставшиеся препятствия для переноса — контракты Java-прокси и ART-хуков, метаданные плагинов, охват Intent и состав контекста меню. [Руководство по переносу](exteragram-port.md) · [Plugin Class](https://plugins.exteragram.app/docs/plugin-class)

## Что у exteraGram есть в публичном API и чего не хватает в BYgram

| Возможность exteraGram | Что происходит в BYgram Full |
| --- | --- |
| **Глобальные обработчики Android Intent.** Документация описывает ссылки и пользовательские Intent, включая фильтры по действию, MIME-типу и категориям. | До Python доходят только `ACTION_VIEW` с URI после разблокировки и для разрешённого аккаунта. Фильтры, приоритеты и остановка стандартной обработки через `before → True` уже работают в пределах этого пути. Например, обработчик `ACTION_SEND` через этот API вызван не будет. [Intents](https://plugins.exteragram.app/docs/intents) · [Диспетчер BYgram](../../TMessagesProj/src/full/java/org/telegram/ui/PluginHost.java#L74) · [Python-адаптер](../../TMessagesProj/src/main/python/intents.py#L20) |
| **Полный контекст меню.** В зависимости от экрана exteraGram документирует `encryptedChat` и `botInfo`. | Все пять типов меню доступны. Адаптер передаёт аккаунт, фрагмент, диалог, сообщение и альбом при наличии, а для обычных диалогов добавляет данные пользователя или чата. Ключи `encryptedChat` и `botInfo` в этом адаптере отсутствуют. Условия видимости, которым нужны эти поля, требуют адаптации. [Контекст exteraGram](https://plugins.exteragram.app/docs/plugin-class#the-on_click-context) · [Адаптер меню BYgram](../../TMessagesProj/src/main/python/base_plugin.py#L118) |
| **Контракт Class Proxy.** Документированы вызов родительского метода через `super()`, вывод сигнатуры конструктора в `new_instance(4)` и параметры `methods=`, `constructors=`, `custom_name=` у `java_subclass`. | Прокси, конструкторные callbacks, `new_java_instance` и `from_java` уже реализованы. Для примера с `ArrayList(int)` в BYgram нужен `new_instance(4, arg_types=["int"])`. В override используется `self.call_super()`. Указанные ключевые параметры декоратора отсутствуют. [Class Proxy](https://plugins.exteragram.app/docs/class-proxy) · [Декоратор BYgram](../../TMessagesProj/src/main/python/extera_utils/classes.py#L8) · [Создание прокси](../../TMessagesProj/src/main/python/extera_utils/classes.py#L133) |
| **Метаданные и фильтрация.** exteraGram читает `__app_version__`, `__sdk_version__`, `__icon__`, `__category__`, а для Elyx документирует prerelease-версии вроде `2.0.0-beta.1`. | Конвертер формирует собственный манифест и сохраняет стабильный ID BYgram для исходного ID. Он не переносит эти поля в проверки и оформление манифеста. Prerelease отклоняется, числовая `1.2` становится `1.2.0`. Нативный манифест BYgram поддерживает собственные диапазоны сборок и PNG/WebP-иконку из пакета. Парсер внешнего HTTPS-индекса также не переносит категории exteraGram. [Метаданные .plugin](https://plugins.exteragram.app/docs/plugin-class#metadata) · [Метаданные Elyx](https://plugins.exteragram.app/docs/elyx/metadata) · [Конвертер](../../TMessagesProj/src/main/python/bygram/_port_extera.py) · [Манифест](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginManifest.java#L73) · [Каталог](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginCatalog.java#L57) |
| **Локаль Elyx и динамическое описание.** Можно выбрать язык Elyx, а плейсхолдер в описании разрешается при загрузке с учётом локали. | Для строк плагина BYgram берёт системный язык и поддерживает явный `locale=`. Имя и описание карточки вычисляются при конвертации, для целого плейсхолдера приоритет у английского. Смена системного языка влияет на чтение строк внутри плагина, но готовая карточка сохраняет текст из манифеста. Python-файлы локализации BYgram читает как литеральные декларации, поэтому вычисляемые значения нужно вынести в JSON/YAML или заменить литералами. [Локализация Elyx](https://plugins.exteragram.app/docs/elyx/localization) · [Строки BYgram](../../TMessagesProj/src/main/python/elyx.py#L280) · [Конвертер Elyx](../../TMessagesProj/src/main/python/bygram/_port_elyx.py#L80) |
| **Загрузка ресурса по URL.** Elyx документирует `Asset.temp_asset_from_url(url, filename)`. | В `Asset` есть `from_path()`, чтение и преобразования ресурсов, включая SVG и Lottie. Вызов `temp_asset_from_url()` потребует адаптации к загрузке в файл и последующему `Asset.from_path()`. [Публичный API Elyx](https://plugins.exteragram.app/docs/elyx/public-api#asset-dir_path-filename-name) · [Asset в BYgram](../../TMessagesProj/src/main/python/elyx.py#L110) |
| **Именованные фоновые очереди.** exteraGram экспортирует восемь констант, в том числе `CACHE_CLEAR_QUEUE`, `PHONE_BOOK_QUEUE`, `THEME_QUEUE` и `EXTERNAL_NETWORK_QUEUE`. | Эти четыре константы отсутствуют в совместимом `client_utils`. Также отличаются строковые значения общих констант. В BYgram `run_on_queue` с `PLUGINS_QUEUE` без задержки использует очередь конкретного плагина, а с задержкой — глобальную очередь Telegram. `get_queue_by_name(PLUGINS_QUEUE)` возвращает глобальную очередь. Это важно для плагинов, которые передают имя строкой или полагаются на порядок задач с задержкой и без неё. [Очереди exteraGram](https://plugins.exteragram.app/docs/client-utils#queues-background-threads) · [Очереди BYgram](../../TMessagesProj/src/main/python/client_utils.py#L161) |
| **ElyxBuilder и встроенный debugpy.** ElyxBuilder генерирует проекты, поддерживает watch, настройки исключений и кэш компиляции. | BYgram предоставляет собственные упаковщик, конвертер и watch с отправкой изменений. Штатного генератора проектов и кэша компиляции ElyxBuilder в этих инструментах нет. Для отладки из IDE адаптер устанавливается на Full Debug отдельно. [ElyxBuilder](https://plugins.exteragram.app/docs/elyx/elyxbuilder) · [Библиотеки exteraGram](https://plugins.exteragram.app/docs/available-libraries) · [Упаковщик](../../Tools/package_plugin.py) · [Dev Server BYgram](dev-server.md) |

## Где возможности совпадают, а поведение различается

| Область | Что учитывать при переносе |
| --- | --- |
| **Telegram hooks и жизненный цикл.** | Поддерживаются хуки запроса, ответа, контейнера обновлений, отдельного обновления и отправки, включая отмену и изменение. Совместимый `BasePlugin` предоставляет `on_plugin_load`, `on_plugin_unload`, `on_app_event`; нативный SDK отдельно различает загрузку и активацию. При импорте BYgram упаковывает исходник в `.byplugin` и хранит его выключенным до разрешения на запуск. [Plugin Class](https://plugins.exteragram.app/docs/plugin-class) · [BasePlugin BYgram](../../TMessagesProj/src/main/python/base_plugin.py) · [Диспетчер перехватов](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginInterceptors.java) · [Установка](README.md) |
| **ART/Xposed.** | BYgram поддерживает `MethodHook`, `MethodReplacement`, `HookFilter` и регистрацию перегрузок. Для запуска нужны `hooks.raw`, диапазоны сборок BYgram и Telegram, точные сигнатуры и успешная проба ART на устройстве. Даже при использовании `hook_all_methods` каждая перехватываемая сигнатура должна быть объявлена. Для переноса предусмотрены `--hook-manifest`, `bygram-hooks.json`, `__bygram_hooks__` и команда `art-targets`. [Xposed exteraGram](https://plugins.exteragram.app/docs/xposed-hooking) · [HookBridge](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/HookBridge.java) · [Сигнатуры ART](dev-server.md) |
| **Аккаунт по умолчанию.** | При обычном вызове модульного helper без `account=` exteraGram использует выбранный в UI аккаунт и предупреждает о расхождении с аккаунтом хука. BYgram отдаёт приоритет аккаунту callback, затем использует выбранный. Например, при событии аккаунта 1 на экране аккаунта 0 вызов `client_utils.send_text(...)` без явного аккаунта пойдёт через 1 в BYgram и через 0 в exteraGram. Явный `account=` фиксирует намерение. Доступ BYgram SDK дополнительно зависит от разрешения пользователя и актуальной сессии аккаунта. [Multi-account](https://plugins.exteragram.app/docs/multi-account) · [client_utils BYgram](../../TMessagesProj/src/main/python/client_utils.py#L34) · [Мост аккаунтов](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginContext.java) |
| **Сообщения и медиа.** | Отправка текста, фото, видео, аудио и документов, HTML/Markdown, редактирование и замена медиа доступны. BYgram принимает файлы из пакета или каталога данных плагина. Числовой `replyToMsg` разрешается среди загруженных сообщений открытого диалога того же аккаунта. Для другого диалога передавайте `MessageObject`. [Client Utilities](https://plugins.exteragram.app/docs/client-utils) · [Отправка BYgram](../../TMessagesProj/src/main/python/client_utils.py#L65) · [Проверка файла](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginContext.java#L446) |
| **Настройки и UI.** | `SimpleSettingFactory`, вложенные страницы, `reload_settings=True`, импорт/экспорт и методы `elyx.settings.get_settings()` / `clear_settings()` уже доступны. Фабрика BYgram строится на собственном RecyclerView. В `create_item` первые два аргумента равны `None`, в `on_click` и `on_long_click` первый аргумент равен `None`. Алиас нужен и у каждого родительского пункта для ссылки на вложенную строку. В диалогах доступны создание до показа и Java-диалог. Bulletins поддерживают целевой фрагмент, кнопки и отмену. [Настройки exteraGram](https://plugins.exteragram.app/docs/plugin-settings) · [Диалоги](https://plugins.exteragram.app/docs/alert-dialog-builder) · [Bulletins](https://plugins.exteragram.app/docs/bulletin-helper) · [Фабрика BYgram](../../TMessagesProj/src/main/python/ui/settings.py#L63) · [Остальные контракты UI BYgram](exteragram-port.md#интерфейс-java-и-медиа) |
| **Показ Bulletin без активного экрана.** | exteraGram документирует запасные варианты через видимый bottom sheet и глобальную фабрику. BYgram использует явно переданный или текущий фрагмент и пропускает показ, если у него нет родительской Activity. [Bulletin Helper](https://plugins.exteragram.app/docs/bulletin-helper) · [Показ в BYgram](../../TMessagesProj/src/full/java/org/telegram/ui/PluginHost.java#L99) |
| **Elyx и зависимости.** | BYgram уже поддерживает `.pyc` Python 3.11, импорт JSON/YAML/TXT, `mvel_execute`, ресурсы и проверку обязательных плагинов через `requires`. Для точки входа `.pyc` метаданные размещаются отдельно. exteraGram устанавливает pure-Python зависимости в общий каталог, переиспользует одну версию и удаляет лишнее при деинсталляции. BYgram разрешает зависимости при конвертации, включает их в итоговый пакет и импортирует локальные библиотеки в пространстве имён плагина. На телефоне резолвер проверяет маркеры окружения, а CLI отклоняет явные маркеры в объявлении. `requests`, `beautifulsoup4`, `lxml` и Pillow уже входят в Full. Установка произвольных бинарных пакетов через обычный резолвер ограничена в обеих системах. [PIP](https://plugins.exteragram.app/docs/pip) · [Elyx Dependencies](https://plugins.exteragram.app/docs/elyx/dependencies) · [Конвертер](../../TMessagesProj/src/main/python/bygram/_port_elyx.py#L120) · [Мобильный резолвер](../../TMessagesProj/src/main/python/bygram/_mobile_pypi.py#L46) · [Сборка](../../TMessagesProj/build.gradle#L12) |
| **Каталоги и доставка.** | BYgram принимает `extera-plugins.json` schema 1, GitHub URL и публичный Telegram-канал. На HTTPS-индекс действует предел в 100 записей и 1 МиБ. В Telegram просматривается до 2000 документов, учитывается дата правки, а дедупликация по ID работает для файлов, метаданные которых удалось прочитать. На фоновые скачивания выделены 32 МиБ и 12 секунд. Поэтому для большого канала часть карточек остаётся с именем файла, а среди них возможны дубли. [Репозитории exteraGram](https://plugins.exteragram.app/docs/plugin-repositories) · [HTTPS-каталог](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginCatalog.java#L57) · [Telegram-каталог](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginChannelCatalog.java#L23) |
| **Разработка и отладка.** | Full Debug поддерживает перезагрузку, передачу изменённых файлов Elyx и команды удалённого дебаггера для VS Code и PyCharm. BYgram также предоставляет собственный протокол доставки готовых пакетов, Pdb и требует токен на каждую команду. Клиент exteraGram, который посылает стандартный запрос без токена, потребует адаптации. [Dev Server exteraGram](https://plugins.exteragram.app/docs/dev-server) · [Elyx Development](https://plugins.exteragram.app/docs/elyx/development) · [Dev Server BYgram](dev-server.md) |

## Возможности нативного SDK и менеджера BYgram

- **Допуск и восстановление.** Отдельное разрешение на запуск установленного пакета, выбор аккаунтов, проверка RSA-подписи автора при её наличии, откат версии, безопасный режим и отдельный процесс восстановления. Официальный каталог BYgram поддерживает модерацию GitHub Release и отзыв конкретного пакета по SHA-256. Плагин исполняется с правами процесса приложения. [Менеджер и каталог BYgram](README.md) · [Хранилище](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginStore.java) · [Подпись](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginSignature.java)
- **Операции BYgram.** Нативный SDK даёт настройки на аккаунт с миграциями, переопределение цветов темы, чтение черновика открытого чата и предпросмотр его замены. Менеджер может показать исходники Python и манифест установленного пакета и экспортировать архив. Такие интерфейсы не описаны в рассмотренном публичном справочнике exteraGram. [SDK BYgram](sdk-v1.md) · [Менеджер BYgram](README.md) · [Справочник exteraGram](https://plugins.exteragram.app/docs)

## Проверка

- `Tools/check_extera_port.py` на Python 3.11.18 завершился успешно. Проверены конвертация, Elyx-байткод, локальные импорты, ресурсы, прокси-интерфейсы и часть совместимых вызовов с подставным Java-мостом. [Проверки совместимости](../../Tools/check_extera_port.py)
- `Tools/check_plugins.py` на Python 3.11.18 остановился на `PluginCatalogCheck.java:30` с `valid dense index rejected`. Фикстура добавляет по 1000 одинаковых целей хуков на манифест, тогда как валидатор разрешает до 256 уникальных целей. Тест рассинхронизирован с контрактом манифеста. По этому падению нельзя судить о работе каталога с валидными плотными индексами. [Тест каталога](../../Tools/PluginCatalogCheck.java#L20) · [Лимит целей](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginManifest.java#L122)
- APK и реальные сторонние плагины в рамках сравнения не запускались. Работа ART на конкретных устройствах, UI-callbacks, IDE-отладка и production-каталог остаются без сквозной проверки. Поведение exteraGram сопоставлено по публичному справочнику. [Матрица проверок BYgram](testing-and-release.md) · [Справочник exteraGram](https://plugins.exteragram.app/docs)
