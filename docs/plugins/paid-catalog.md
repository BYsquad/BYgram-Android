# Платный каталог BYgram

## Автор и покупатель

В Android откройте **Настройки → Настройки BYgram → Плагины → Официальный каталог → Добавить плагин**. Заполните цену в Stars, TON или обе цены и выберите подписанный `.byplugin`. Для первой публикации нужен новый ID. Следующая версия подаётся с тем же ID, под тем же Telegram-аккаунтом и с тем же ключом автора. Статус заявки и остатки автора показаны на странице подачи. Нулевое или пустое поле цены скрывает этот способ продажи.

Кнопка «Приём платежей автором» открывает веб-страницу BYgram. Для Stars введите токен отдельного торгового бота из BotFather. BYgram проверяет бота и регистрирует свой webhook, если бот свободен или уже подключён к этой странице. Stars за новые заказы поступают на баланс этого бота. Отключение или замена бота действует на новые заказы. Сохраняйте рабочий токен старого бота для сверки и возвратов. Для TON войдите тем же Telegram-аккаунтом и подтвердите активный кошелёк V3R2, V4R2 или V5R1 через TON Connect. Один подтверждённый адрес на сеть используется для всех плагинов автора. Без адреса в выбранной сети TON скрывается. Смена кошелька и отключение приёма TON применяются к новым заказам. Ранее созданный заказ сохраняет исходный адрес.

Модератор открывает кандидата в разделе «Модерация плагинов», проверяет конкретный архив и подтверждает SHA-256 при публикации. Приостановка продаж убирает цены, владельцы сохраняют загрузку. Отзыв хеша прекращает выдачу этой версии и передаёт хеш клиентскому списку отзывов.

Покупатель выбирает способ оплаты и подтверждает условие о возврате до инвойса Stars или запроса TON. В **Моих покупках** можно проверить заказ и получить пакет под тем же Telegram-аккаунтом. Оплата открывает загрузку, а установка и включение управляются отдельно. Веб-витрина поддерживает вход через Telegram и оплату Stars или TON. Stars оплачиваются через штатный Telegram-инвойс торгового бота автора.

## Реализация

- Сервер хранит точные подписанные архивы как `MEDIUMBLOB` в MySQL. Доступ к архиву проверяется на каждую загрузку. Упаковка и код плагина остаются совместимыми с SDK v1.
- `plugin-store-catalog.php` отдаёт платную часть каталога v2. Клиент объединяет её с бесплатным индексом v1. Платные карточки содержат SHA-256, метаданные и цены. Тело архива выдаётся через авторизованное действие `store_download`.
- `store_*` использует подтверждённую сессию Telegram-аккаунта, включая вход из браузера BYgram, независимо от переключателей проверки Activity API. `store_order` сохраняет покупателя, условия, сумму, способ, продавца и сеть на момент заказа. Статусы клиента и кошелька только показывают ход оплаты. Право покупки выдаёт подтверждённое событие провайдера в транзакции MySQL.
- `plugin-store-stars.php` принимает webhook отдельного торгового бота. `plugin-store-web.php` обслуживает standalone-витрину, кассу, привязку кошелька и манифест TON Connect. Сервер проверяет `ton_proof` по одноразовому запросу и действующему публичному ключу стандартного кошелька в сети. `plugin-store-sync.php` сверяет Stars и переводы по адресам, зафиксированным в недавних TON-заказах. Личные переводы автора без метки заказа BYgram не заносит в таблицу платежей. Для пилота окно сверки составляет семь дней с создания заказа.

## Staging и пилот

1. Применить миграции [каталога](../../server/activity-api/migrations/20261118_plugin_store.php) и [кошельков авторов](../../server/activity-api/migrations/20261118_plugin_store_author_wallets.php) через серверный CLI или планировщик хостинга. Свежая установка может использовать `schema.sql`. Проверка подписи использует Sodium или поставляемый архив Sodium Compat v2.5.2. Для пакетов до 10 МиБ проверить лимит HTTP-тела от 14 МБ, достаточную PHP memory limit для JSON и `max_allowed_packet` MySQL от 32 МиБ. Включить резервные копии таблиц с релизами и правами покупок.
2. Перенести поля из [примера конфигурации](../../server/activity-api/config.example.php) в серверный `config.php`. Флаги `plugin_store_enabled`, `plugin_store_sales` и `plugin_store_live` по умолчанию выключены. Использовать отдельный набор аккаунтов и отдельную БД для тестовых покупок. `plugin_store_authors` при необходимости ограничивает список авторов пилота.
3. Для sandbox Stars указать отдельный токен бота в тестовой сети Telegram, оставить `plugin_store_stars_test=true` и зарегистрировать `setWebhook` для `plugin-store-stars.php` с `secret_token`, `pre_checkout_query` и `message`. Токен авторизации пользователей BYgram хранится отдельно. Предупреждение и условия продажи должны быть доступны покупателю до оплаты.
4. Для TON оставить `plugin_store_ton_test=true`, указать HTTPS URL каталога API в `plugin_store_url` и подключить testnet-кошелёк в профиле автора. Публичный манифест должен ссылаться на доступный PNG, по умолчанию используется `assets/bygram-logo.png` сайта. При отдельном домене передать `plugin_store_icon_url`. Проверить доступ к TON Center v2 и v3. `plugin_store_ton_address` применяется только при сверке и учёте старых заказов с общим получателем.
5. Развернуть сервер и админку, затем включить `plugin_store_enabled` и `plugin_store_sales`. Для боевой сети установите `plugin_store_live=true` и `plugin_store_ton_test=false`. При проверке заказа в кассе или «Моих покупках» сервер сам сверяет TON. Периодический вызов `php plugin-store-sync.php ton` подбирает платежи, если покупатель закрыл кассу. Для Stars периодически запускайте `php plugin-store-sync.php stars` для сверки. Остановка новых заказов через `plugin_store_sales` сохраняет проверку принятых платежей и выдачу покупок.

Платежи выгружаются из админки в CSV владельцем. Выплаты с прежнего общего Stars-бота происходят вручную и записываются командой `php plugin-store-operations.php payout-record stars <telegram-id> <сумма-в-единицах-учёта> <ссылка-на-выплату>`. Повтор записи с той же ссылкой идемпотентен. При прямой оплате TON вся сумма поступает автору, поэтому выплата через BYgram не начисляется.

Обычного возврата по желанию покупателя нет. Для обязательного возврата Stars оператор использует `php plugin-store-operations.php refund stars <charge> [merchant]` после проверки обращения. При неоднозначном ответе сверяет историю Stars перед повтором. Перед переводом TON покупатель подтверждает, что платит автору и команда BYgram не несёт ответственности за возврат средств, полученных автором, в пределах, допускаемых законом. Обязательный возврат рассматривается с автором. После сверки исходящего перевода оператор может зафиксировать подтверждённый возврат командой `php plugin-store-operations.php refund-record ton <charge> <outgoing-hash>`.

## Локальная проверка без денежных переводов

```sh
BYGRAM_TEST_LOCAL=1 BYGRAM_TEST_DB_DSN=mysql:host=localhost \
  php -d zend.assertions=1 -d assert.exception=1 server/activity-api/plugin-self-test.php
```

Тест создаёт отдельную временную БД, подписывает тестовый архив и прогоняет входящие события с подставными ID и данными TON. Вызов ответа на pre-checkout заменяется функцией-фикстурой. В проверке покрыты защита выдачи, двойная доставка, чужой покупатель, возврат, раздельные сети, недоплата и перевод без назначения. В рабочем HTTP API нет переключателя, которым покупатель мог бы подтвердить собственный платёж.

`python Tools/check_plugins.py` проверяет разбор обоих поколений каталога и существующие ограничения подписи/установки. Проверка кодировки TON включает чтение BOC и адреса независимым `@ton/core`. Staging с тестовым ботом и кошельком нужен для сквозной проверки штатного платёжного окна на устройстве.

Sodium Compat поставляется как официальный PHAR из [релиза v2.5.2](https://github.com/paragonie/sodium_compat/releases/tag/v2.5.2). SHA-256 архива `5d3beca6e5ce9e5f43c62794791a8fc4ec76e40c12fbd4eba1280168bf697a0f`. HTTP-доступ к архиву закрыт.

Для внешнего ключа шифрования токенов задайте `plugin_store_stars_key` до подключения первого бота. Если ключ не задан, ключ выводится из токена бота входа. При ротации ключа или исходного токена нужно перенести зашифрованные учётные данные. Примените миграцию `20261119_plugin_store_author_bots.php` до обновления кассы.
