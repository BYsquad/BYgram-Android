# Текущий статус Android-плагинов — 01.11.2026

Продолжение: [новый hook и аудит оставшихся работ](hook-update-and-audit-2026-11-01.md). Этот документ описывает предшествующий этап и заменяет противоречивые статусы прежних проходов. Задание: пункты 1, 3–8 из аудита. Финальная приёмка текущих изменений выполняется; прежний Release с каталогом уже доставлен, новый итоговый APK этого задания пока не собран.

## Реализованные исправления

- Lifecycle (включая import/constructor, migration, settings descriptors, disable/unload) выполняется вне management queue; следующий проход убрал общий пул в пользу отдельного daemon-потока на вызов. Timeout 5 s инвалидирует scope, сохраняет restart-required и не позволяет менять пакет/данные живого поколения. Зависшие потоки не убиваются небезопасно; зависшее поколение требует restart, но не отнимает общий lifecycle worker у других плагинов. Произвольный код Java/native всё ещё доверенный и способен блокировать VM.
- Кандидатами raw hooks являются 64-bit primary arm64/x86_64 API 24–37. Закрытый Service `:plugin_probe` запускает встроенный Python/native/GC probe без пользовательских плагинов и Telegram initialization. Watchdog 15 s завершает probe; manager ждёт максимум 20 s. Crash/timeout блокирует backend до restart. Это проверка конкретного устройства при запуске, не аппаратная аттестация всех OEM. В этом снимке native retention до restart ещё оставлен; в последующем обновлении hook заменён физическим unhook.
- Каталог имеет отдельный сетевой пул, отмену, общий deadline 30 s, connect/read timeout, фильтр устаревших callbacks и понятные сообщения об отказах. Локальная установка работает независимо от каталога.
- Изменения theme overrides обновляют общие paints, ThemeDescription известных живых fragment, tree invalidation и recycled pools; resume применяет пропущенную ревизию. Навигация/черновики не пересоздаются. Цвета custom View вне ThemeDescription остаются ответственностью автора.

## Заявки и модерация

Android: Плагины → Добавить плагин в каталог. Автор отправляет HTTPS-ссылку на публичный `github.com/owner/repo`. Используются существующие подписанные BYgram sessions; список заявок доступен только владельцу. До 5 заявок в сутки, одна pending/review на репозиторий.

Стабильный GitHub Release содержит один `.byplugin` до 10 MiB. Тег `v1.2.3` либо `1.2.3` совпадает с `manifest.version`. Администратор открывает `/api/plugins.php` из существующей панели, получает последний стабильный Release, скачивает **точный кандидат** и проверяет код/поведение. Одобрение фиксирует hash кандидата; замена его после открытия страницы отклоняется. Пакет публикуется immutable по SHA-256, index — последним atomic rename под lock. Репозиторий закрепляется числовым GitHub repository ID, запрещён захват чужого plugin ID и откат опубликованной версии.

Каждый новый Release требует новой заявки и модерации: новая upstream-версия не обходит проверку. Никакой код плагина на сервере не исполняется. GitHub API/asset transport ограничен HTTPS allowlist, размером и timeout; ZIP проверяется без извлечения в webroot. Android повторяет полный production validator. Скачивание каталога и установка оставляют код выключенным.

Модерация означает решение администратора по конкретному пакету, не sandbox, не проверку владения GitHub-аккаунтом заявителем и не криптографическую подпись автора. Плагины исполняются с правами клиента. Установка из файла остаётся доступной с предупреждением доверия.

## Изменённые системные интерфейсы

- `PluginRecovery`/`ApplicationLoader`: отдельный probe-process пропускает Telegram initialization, recovery сохраняет независимость.
- Full `PluginHost`: обновление цветов существующих системных страниц через ThemeDescription и Telegram paints.
- Менеджер: отмена каталога, native-страница заявки и статус модерации/GitHub Release.
- Подписанный API: `plugin_submit` и `plugin_submissions`; существующие auth/licensing/profile operations не заменены.
- Сервер: таблица `plugin_submissions`, admin-only moderation с CSRF; immutable каталог и сохранённые GitHub IDs/версия/hash.
