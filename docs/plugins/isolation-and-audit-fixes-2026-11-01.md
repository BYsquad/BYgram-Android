# Android: исправления аудита плагинов — 01.11.2026

Статус: в работе. Нового APK нет. Этот проход следует после reliability-and-moderation-2026-11-01.md.

## Исправления

1. PHP manifest validator отклоняет Python keywords в имени класса и проверяет компоненты entrypoint/icon. Перед публикацией повторно проверяются manifests индекса. Android пропускает отвергнутый manifest, оставляя доступными остальные валидные записи; структурные ошибки индекса, пути пакетов, hash/size и provenance продолжают отклоняться.
2. `PluginWork` принадлежит одному `PluginContext`: два потока, очередь 32, отменённые queued задачи удаляются. Закрытие scope прерывает работу кооперативно. Произвольный Java/Python-код, игнорирующий interruption, этим безопасно уничтожить нельзя.
3. `PluginFiles` читает URI в отдельном bounded pool, с лимитом bytes и deadline 30 s. Cancel/timeout завершают запрос однократно; потенциально блокирующий cancel/close провайдера выполняется отдельно. Проверка request повторяется в management queue до stage/import mutation. Два неотвечающих провайдера могут исчерпать файловый пул, но не очередь отключения плагинов или каталог.

## Исполнение и доверие

- Изоляция не добавляется по решению владельца. И локальные, и каталожные плагины сохраняют полный Java/raw hooks API и работают с правами клиента.
- Перед установкой файла вне каталога BYgram требуется отдельное подтверждение предупреждения о доступе к аккаунтам, сообщениям, файлам, сети и Java/raw hooks. Источник берётся из результата host installer, а не из авторского manifest. Отмена/закрытие предупреждения удаляет staged package. Код остаётся выключенным после установки.
- Подпись содержимого RSA/SHA-256 проверяет все файлы пакета, кроме самого signature.json. Ключ автора закрепляется для обновлений; его замена/удаление отклоняется. Это криптографическая идентичность ключа, а не удостоверение имени/личности автора и не sandbox.
- Новые публикации модерации требуют подписи автора. Существующие неподписанные записи каталога остаются совместимыми и обозначаются неподписанными. Источник «каталог» не гарантирует безопасность кода.
- SDK callbacks с host main thread и `ui.run` выполняются асинхронно в последовательной очереди плагина, с deadline 5 s и restart quarantine. Чтение черновика переносится host на main thread, с ограниченным ожиданием worker. Прямой Java/Handler/raw-hook код доверенного плагина по-прежнему способен блокировать UI/VM; сохранение полного API не даёт возможности безопасно останавливать такой код.

## Системные интерфейсы

Изменены файловые операции менеджера, отмена на native странице плагинов и обработка ошибок en/ru/uk. Стандартные страницы чатов/профиля Telegram этим исправлением не менялись. Документ фиксирует и баги, не связанные с кастомными настройками BYgram.
