# BYgram Full и exteraGram: сравнение систем плагинов

13 ноября 2026 года

Сравнение фиксирует состояние перед доработкой совместимости. Текущие возможности и оставшиеся различия описаны в [руководстве по переносу](exteragram-port.md).

**BYgram Full уже покрывает основные сценарии exteraGram:** перехваты запросов, ответов, обновлений и отправки; отправку медиа; импорт `.plugin` и Elyx; подключаемые каталоги; перезагрузку плагина с компьютера. **exteraGram по-прежнему даёт авторам более широкий API**: больше точек встраивания в интерфейс, богаче контекст меню и операции с сообщениями, есть зависимости между плагинами и синхронизация изменений по отдельным файлам. Отличительная сторона BYgram — контроль запуска конкретного пакета, доступ SDK по аккаунтам, проверка ключа автора, откат и восстановление после сбоев.

Срез BYgram: Android-репозиторий `BYgram-mobile`, HEAD `856c8fb773207b69be3727b8100471d3185b09a7` и текущее рабочее дерево, включая новые файлы вне Git. Источники по BYgram ниже — реализация и тесты. Наличие кода в этом срезе не доказывает его наличие в публичном APK. В Lite точки входа заглушены. Для exteraGram источник — опубликованный SDK: [введение](https://plugins.exteragram.app/docs) указывает Python 3.11 и SDK 1.4.4.3; новые account helpers имеют отдельный минимум [1.4.5.0](https://plugins.exteragram.app/docs/multi-account).

### Где импортированный плагин потребует правок

- **Фильтр исходящих сообщений или TL-запросов.** Основной контракт `add_hook`, `add_on_send_message_hook` и `HookResult` уже сопоставим. Сначала стоит проверить конкретные типы запросов и путь отправки. Hooks выполняются синхронно на потоке вызывающей стороны: порог 16 мс в BYgram пишет запись в журнал, но не останавливает медленный callback. [Адаптер](../../TMessagesProj/src/main/python/base_plugin.py#L82) · [Вызов](../../TMessagesProj/src/full/java/org/telegram/messenger/plugins/PluginContext.java#L233)
- **Действие над сообщением, которому нужен текст или Java-объект.** Кнопку можно перенести; обработчик, который читает `context["message"]`, нужно адаптировать. То же относится к плагинам, которые вызывают `send_message` с расширенными параметрами или добавляют `Custom` в настройки. [Контекст BYgram](../../TMessagesProj/src/full/java/org/telegram/ui/PluginHost.java#L167) · [Контекст exteraGram](https://plugins.exteragram.app/docs/plugin-class)
- **Большой Elyx-плагин.** Проект с Python-модулями, строками и pure-Python wheels имеет путь импорта. Плагин с `requires`, Xposed API exteraGram или специфическими модулями вроде `android_utils`, `hook_utils` и `file_utils` требует адаптации; одноимённых Python-модулей в дереве BYgram SDK нет. [Дерево Python SDK](../../TMessagesProj/src/main/python/) · [Модули exteraGram](https://plugins.exteragram.app/docs)

Если цель — запускать больше плагинов exteraGram без изменений, первый практический шаг — прогнать на Android три реальных образца: фильтр отправки, действие над сообщением и Elyx-проект с ресурсами и зависимостями. Затем закрывать разрывы по фактическим ошибкам импорта и вызова. Уже видимые кандидаты — контекст меню сообщения, совместимость настроек и распространённые helper-модули.

### Границы проверки

- `python Tools/check_plugins.py` завершился с кодом 0 на Windows, с Python 3.15.2 на хосте. Прогон охватил конвертацию exteraGram/Elyx, изоляцию импортов, тест диспетчера Telegram на JVM, валидацию индексов и пакетов, подпись, обновление, откат и восстановление реестра. Часть Python-тестов использует подставной Java-мост; тесты каталога не заменяют загрузку с реального канала. [Набор проверок](../../Tools/check_plugins.py) · [Импорт и совместимость](../../Tools/check_extera_port.py) · [Тест диспетчера](../../Tools/PluginInterceptorsCheck.java)
- APK не собирались и не запускались. Не проверены фактическое покрытие перехватов на Android, ART, отправка медиа, UI, соединение с IDE и работа production-каталога. exteraGram сравнивался по справочнику; число совместимых плагинов или доля успешных импортов не измерялись.
- Разрешения и привязка аккаунта относятся к штатному SDK. Python и Java выполняются в процессе клиента; отдельное пространство импортов, модерация и подпись пакета не изолируют код плагина.
